# 旅程还原

在客户问题跨越较长时间、多个步骤、角色或渠道，团队只看到自己负责的一小段时使用。

从触发任务的事件开始，按时间还原客户为了取得结果经历的行动、决定、等待、交接、失败和恢复。材料可以来自访谈、观察、截图、事件卡、分析数据和支持记录。把客户视角的体验旅程与提供方的后台流程分开呈现，再标出两者连接和断裂的位置。

旅程图不需要精美，也不应靠会议室想象补齐。每个关键步骤标明证据来源、客户当时的目标和遇到的障碍；未知部分继续保持为空或转化成研究问题。

当团队能够看见客户完整任务、关键时刻和组织边界造成的问题，并能判断本产品应改变其中哪一段时停止。随后把材料交给研究综合或问题重构。

来源：[GOV.UK Researching User Experiences](https://www.gov.uk/service-manual/user-research/researching-user-experiences)、[GOV.UK Map a User's Whole Problem](https://www.gov.uk/service-manual/design/map-a-users-whole-problem)。

# PR/FAQ

在产品方向已经初步形成，需要让客户价值、未来体验和内部难题同时变得可讨论时使用。它不适合替代尚未完成的客户研究或产品发明。

新闻稿面向客户，用普通语言说明产品服务谁、客户原来面对什么、现在获得什么结果、体验怎样改变以及为什么值得选择。外部 FAQ 回答客户在使用、切换、信任、价格和异常情境中的真实疑问。内部 FAQ 处理技术、成本、运营、法律、渠道、依赖、指标和失败条件。

先写最重要且最难回答的问题，不追求文档篇幅。答案缺少证据时明确写成假设和验证责任；答案暴露产品逻辑不通时返回问题或发明阶段，而不是用更好的文案修补。

当不了解项目的决策者、设计者和工程师能够形成同一个产品画面，关键异议已经显露，下一步应验证或投入什么已经清楚时停止。

来源：Amazon Web Services, [Introduction to Working Backwards](https://d1.awsstatic.com/events/Summits/reinvent2023/INO101_Define-your-next-%241B-opportunity-Introduction-to-Working-Backwards.pdf)。

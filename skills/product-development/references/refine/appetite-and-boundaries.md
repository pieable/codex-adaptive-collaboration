# 投入与边界

在产品概念可能无限扩张、估算讨论代替价值取舍，或者团队无法判断什么程度算本轮完成时使用。

先根据问题价值决定愿意投入的时间、人员和不可承担的风险，再设计能在该投入内成立的产品范围。投入约束方案，而不是等全部需求列完后被动接受估算。无法缩小时，寻找仍能独立产生客户价值的较小完整结果。

明确核心体验、允许实施者调整的范围、有意不做的情境，以及可能使工作失控的高危难点。提前解决会拖垮交付的未知；普通实现选择保留给负责团队，不把边界写成逐项任务清单。

当团队知道为什么值得投入这么多、在期限内必须成立的客户结果是什么、遇到什么情况应缩小或停止时结束。边界以后可以根据新证据改变，但不能在实现中静默漂移。

来源：[Basecamp Shape Up: Set Boundaries](https://basecamp.com/shapeup/1.2-chapter-03)、[Write the Pitch](https://basecamp.com/shapeup/1.5-chapter-06)。

# 测试与迭代判断

在准备运行产品实验、原型测试或真实发布验证，需要避免事后按偏好解释结果时使用。

测试前写清当前假设、代表性客户和环境、需要观察的行为或结果、会支持或否定判断的证据，以及测试不能证明什么。参与者应与目标客户和使用情境相符；早期小样本适合发现机制和可用性问题，不自动证明市场规模。

测试时让客户按真实目标行动，观察其理解、选择、错误、变通和结果，少做推销式解释。分析时区分观察、解释和决定，保留反例与证据强度。结果可以要求修改方案，也可以返回客户研究、问题定义或产品发明，不默认只调整原型细节。

当证据足以作出当前范围内的继续、修改、补充研究或停止决定时结束本轮。无法区分不同解释时，不宣布成功，设计下一项能消除分歧的验证。

来源：[Google Design Sprint: Validate](https://designsprintkit.withgoogle.com/methodology)、[GOV.UK User Research](https://www.gov.uk/service-manual/user-research/how-user-research-improves-service-design)、[IDEO Get Feedback](https://www.designkit.org/methods/get-feedback.html)。

# `workflow-state-distiller` 规则理由

本文件不参与运行。维护本 Skill 时还必须读取 `CHANGELOG.md` 和 `references/eval-cases.md`。

## WSD-01 只有当前理解不能可靠指导下一步时才完整蒸馏

- **状态：** `current-effective`
- **行为：** 零散或失效理解会导致遗漏、误判范围或改变下一步时重建；信息多、普通返工、执行报错或等待外部状态本身不触发。
- **理由：** 状态蒸馏用于恢复行动依据，不是每次对话的总结仪式。
- **来源：** `SKILL.md` description、“加载后的范围判断”；`CHANGELOG.md`。
- **验证：** 评测案例覆盖应触发和不应触发情形。
- **改变条件：** 触发依据是行动可靠性，不是纠正次数、对话长度或用户情绪。

## WSD-02 当前状态只保留会改变行动的五类内容

- **状态：** `current-effective`
- **行为：** 维护目的、背景、行动、结果、边界；字段可为空，不填表；记录来源、适用情境和失效条件。
- **理由：** 这五类足以决定要做什么、为什么、交付什么和能做到哪里，其他历史留在原始记录或路线图。
- **来源：** `SKILL.md`“维护的任务状态”；Root Base 的任务理解结构。
- **验证：** 评测案例覆盖局部修正和状态分散。
- **改变条件：** 可以自然表达和省略空项，不能用格式精简删掉会改变行动的内容。

## WSD-03 直接证据、决定、原因假设和未形成偏好分开

- **状态：** `current-effective`
- **行为：** 用户体验可证明结果不符合需要，但不能单独证明原因；原因解释标明是谁提出并等待独立证据或后续选择。
- **理由：** 模型容易把用户一次解释或自己的推断升级成长期真理，随后在其他场景过度套用。
- **来源：** `SKILL.md`“维护的任务状态”；`CHANGELOG.md` 证据强度记录。
- **验证：** 评测案例覆盖相同反馈的不同原因。
- **改变条件：** 新证据可以升级、缩小或撤回解释，不能只累加禁令。

## WSD-04 理解强度与证据和适用范围相称

- **状态：** `current-effective`
- **行为：** 区分明确事实、局部修正、工作假设、候选原则、已确认原则和硬边界；正向规则也不能写得比证据更强。
- **理由：** “这次改短”不能自动变成“所有回答必须极短”，多次出现也不自动证明跨项目原则。
- **来源：** `SKILL.md`“这些理解有多确定”“要求写多重”；`CHANGELOG.md`。
- **验证：** 评测覆盖局部修正、硬边界、反例撤回。
- **改变条件：** 用户明确确认或不同项目证据支持后才能升级；反例可随时降级。

## WSD-05 用删除测试判断一项理解是否值得保留

- **状态：** `current-effective`
- **行为：** 删除某项后若目标、输出、提问、权限、风险和下一步都不变，就不进入当前状态；多个解释导向同一安全行动时只保留最窄假设。
- **理由：** 防止把每次纠正堆成重复长期规则，也避免模型为解释完整保留无行动作用的原因。
- **来源：** `SKILL.md`“用下一步行动检验理解”“从不要这样弄清应该怎样”；`CHANGELOG.md`。
- **验证：** eval cases 直接覆盖删除测试。
- **改变条件：** 高风险反向边界若删除后会重新包含具体危险情形，必须保留。

## WSD-06 提问、样本和继续执行按信息价值选择

- **状态：** `current-effective`
- **行为：** 不同答案改变目标、结构、权限、不可逆操作或用户结果时问；可逆小成果更能暴露偏好时先给样本；同一安全行动可继续。默认先问最有价值的问题，开放表达成熟后才建议 Plan mode。
- **理由：** 既避免大规模猜测，也不把普通细节全部推给用户。
- **来源：** `SKILL.md`“决定继续做、先给样本还是提问”；Root Base 提问规则。
- **验证：** 评测有对应情形；真实长期交互负担待观察。
- **改变条件：** 问题堆积会增加偏差，不恢复“统一攒到决定点”的路线。

## WSD-07 失败只在改变后续判断时进入当前状态

- **状态：** `current-effective`
- **行为：** 保存“原判断—推翻证据—当前影响”；完整分叉、回退和废弃路线交 Route Mapper，当前状态只保留仍有效的结果。
- **理由：** 调试日志会淹没当前任务，但否决路线和新边界又不能丢失。
- **来源：** `SKILL.md`“失败与探索历程”；`workflow-route-mapper`。
- **验证：** CHANGELOG 和评测覆盖失败是否进入状态。
- **改变条件：** 已解决且不再约束后续的报错从当前状态删除，但原始记录仍保留。

## WSD-08 规则只进入一个合适的长期承载层

- **状态：** `current-effective + conditional`；2026-08-30 已重新确认保留
- **行为：** 当前任务、项目事实、项目规则、领域 Skill 和全局规则按适用范围选择唯一主要来源；样本和失败不因一次认可就升格。
- **理由：** 同一句规则复制多层会漂移，也会让 subagent 收到 Root 才需要的内容。
- **来源：** 当前 `SKILL.md`“决定理解保存在哪里”；`CHANGELOG.md` 阶段六和“当前生效状态”；Git `22d1993`。
- **验证：** CHANGELOG 记录用户于 2026-08-12 判断整章是有意删除；Git `22d1993` 于 2026-08-17 又完整恢复但没有记录原因。2026-08-30 用户重新确认这项能力可以保留、未观察到危害，同时明确它只是附带作用，不能改变“蒸馏和校准当前理解”的主目的。
- **改变条件：** 部署位置和职责层不同可以记录镜像关系，但不建立多个编辑权威。

## WSD-09 维护本 Skill 必须用案例做前向测试

- **状态：** `current-effective`
- **行为：** 重写时读取 eval cases，比较触发、易混淆和不触发情形，检查范围、力度、下一步和提问；不能用更短或否定句更少证明保真。
- **理由：** 这类规则的一个词就可能改变适用范围，仅静态读起来顺畅无法发现行为漂移。
- **来源：** `SKILL.md` 末段；`CHANGELOG.md`；`references/eval-cases.md`。
- **验证：** 已有案例集；真实模型版本变化后需重新跑代表性案例。
- **改变条件：** 案例可增加或淘汰，但不能与候选正文同时改写来证明候选正确。

# Workflow State Distiller 演变记录

本记录说明公开版本的设计演变，不包含私人会话、备份位置或内部项目资料。当前生效规则以 `SKILL.md`、`agents/openai.yaml` 和 `references/eval-cases.md` 为准。

## 当前目标

用户不必在任务开始时一次说清完整规格。这个 Skill 帮助 Codex 从明确表达、实际选择、纠正、试用结果和失败路线中，维护仍会改变行动的目标、背景、输出和边界。

它区分用户已经决定的内容、可核实事实、暂时解释和仍未形成的偏好。隐含目标只能在证据支持的范围内帮助选择路线，不能扩大授权或覆盖明确要求。

## 公开演变摘要

- **从局部禁令到任务状态：** 不把每次纠正机械升级为长期规则；优先恢复这些反馈共同保护的目的和当前工作状态。
- **证据与可撤回：** 将理解按明确事实、局部修正、工作假设、候选原则、已确认原则和硬边界区分；反例可以缩小、替换或撤回已有理解。
- **渐进形成规格：** 允许目标、背景、输出和边界在协作中逐步明确；从已知部分开始，通过可逆样本或高价值问题降低关键不确定性。
- **普通语言与删除测试：** 精简以是否改变下一步行动为准，而不是字数或否定句数量；删除测试用于识别被其他规则完全覆盖的内容。
- **保存位置：** 已确认的理解按适用范围留在当前任务、项目资料、项目规则、可复用 Skill 或全局规则层；同一事实或规则只保留一个主要来源。
- **隐含目标的权限边界：** 明确指令决定交付结果和授权。未经确认的推断不能单独改变结果、范围或必要验证。

## 验证边界

本 Skill 的静态检查覆盖 YAML frontmatter、结构和评估案例。文件可解析不代表宿主已加载，也不替代真实任务中的行为验证。

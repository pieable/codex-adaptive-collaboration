# `eli5` 规则理由

本文件不参与运行。

## E-01 简化的目标是减少理解背景，不是删事实

- **状态：** `current-effective`
- **行为：** 用户要求 ELI5、按特定受众解释，或复杂内容需要让不负责实现的人快速掌握时使用。默认面向不负责日常实现的成年项目负责人；第一层先给可行动的全局图景，第二层再展开术语、机制和取舍。本来已经简单且无需解释的短回答不调用本 Skill。
- **理由：** 用户经常没有相关知识和经验，需要看懂 Root 在做什么、计划到了哪里，而不是阅读实现者的原始细节。ELI5 不是真的把用户当五岁小孩；简单问题已经没有背景负担时，再加载一套解释结构只会增加时间和文字。
- **来源：** `SKILL.md` 的 description、“先确定受众和用途”“分两层解释”；Claude Code ELI5 的受众适配思想；2026-08 用户校准。当前成年负责人默认与视觉规则是后续本地设计，不是 Claude 原文。
- **验证：** 静态结构和短探针通过；真实长任务持续可读性待验证。
- **改变条件：** 用户指定年龄、专业背景或角色时按实际受众调整。

## E-02 视觉形式按用户理解成本选择

- **状态：** `current-effective + unverified`
- **行为：** 流程、层级、因果、路线和当前位置明显适合视觉时先用图建立全局。普通静态关系优先 Mermaid；只有交互、筛选、动态关系或多视图切换确实帮助理解时才使用自包含 HTML。图没有明显优于短段落时直接用文字。
- **理由：** 大量文字读取慢而且容易让非实现者失去全局。Mermaid 制作成本低，适合多数结构；HTML 表达能力更强但制作和阅读成本也更高，只在交互性产生真实收益时使用；内容很短时纯文字反而最省力。
- **来源：** `SKILL.md`“视觉优先”；Root Base“过程交流”；`subagent-architecture/rule-rationale.md` R27、R30；用户本轮确认。视觉选择不是本机 Claude ELI5 原文。
- **验证：** 规则存在；真实长任务图是否持续可读尚未验收。
- **改变条件：** 新的可视化工具在更低成本下明显提高理解时可以采用；选择形式仍以减轻用户理解负担为准。

## E-02A 一张图只建立一个主要心智模型

- **状态：** `current-effective + unverified`
- **行为：** 一张图围绕一个主要关系组织，图后通常只保留变化、结论和下一步等少量要点，不把原始 agent 报告搬到图旁。
- **理由：** 图的作用是让用户一次抓住一个整体结构。把多个不同关系和长篇说明挤进同一张图，会重新制造与长文本相同的注意力负担；少量文字负责告诉用户这张图对当前决定意味着什么。
- **案例：** 历史阶段报告只列模块和测试，用户仍不知道整体到了哪里。
- **来源：** `SKILL.md`“视觉优先”；Prompt Lab R30；当前本地规则。核对本机 Claude ELI5 原文后，未发现“一图一个模型”或“图后三点”，因此不再把它们归为 Claude 原规则。
- **验证：** 静态文字明确；真实长任务图是否持续可读仍未验证。
- **改变条件：** 一个简单关系只需一句话时不用图；图后要点数量服从信息需要，“三个”是常用轻量形态，不是必须凑满的模板。

## E-03 视觉报告由 Root 形成，subagent 只交证据

- **状态：** `current-effective`
- **行为：** 下属返回结果、证据和限制，Root 根据整体任务形成用户可读的图和解释，不把原始报告拼接给用户。
- **理由：** 只有 Root 保留完整任务框架和用户理解，subagent 无法可靠解释跨阶段位置。
- **来源：** `SKILL.md`；Root Base；Agent 责任链。
- **验证：** 静态责任清楚；真实阶段报告待验证。
- **改变条件：** 独立小任务由当前 Root 自己形成报告，不为此增加阶段层级。

## E-04 图和简单语言不替代完成证据

- **状态：** `current-effective`
- **行为：** 事实、推断和未知分开；不能为了易懂删除会改变决定的前提、风险、边界和不确定性，也不能让漂亮图表证明任务完成。重要结论附最短的文件、页面、运行结果或链接，使用户能够按需核验。
- **理由：** 视觉是降低理解成本的载体，不是把局部进度包装成成功。最短依据让用户知道结论不是凭空产生，能够放心采用，又不必阅读完整证据台账。
- **案例：** C-14。
- **来源：** `SKILL.md`“保持准确”；全局验证责任。
- **验证：** 静态规则明确。
- **改变条件：** 可以减少术语和背景，但不能改变证据层或结论强度。

## E-05 语言随受众变化

- **状态：** `current-effective`
- **行为：** 儿童用短句和熟悉类比；管理者重结果、风险和成本；工程师保留标准机制术语。默认用户是需要全局理解的成年负责人。
- **理由：** 同一种“简单”对不同受众会失真，过度幼儿化和术语堆砌都增加理解成本。
- **来源：** `SKILL.md`“根据受众调整”。
- **验证：** 静态原则明确；不同受众案例仍可补充。
- **改变条件：** 用户明确要求另一种解释风格时以用户要求为准。

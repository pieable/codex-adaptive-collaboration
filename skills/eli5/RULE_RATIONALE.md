# `eli5` 规则理由

本文件不参与运行。

## E-01 简化的目标是减少理解背景，不是删事实

- **状态：** `current-effective`
- **行为：** 按受众和用途解释，默认面向不负责日常实现的成年项目负责人；第一层先给可行动的全局图景，第二层再展开术语、机制和取舍。
- **理由：** 用户经常没有相关知识和经验，需要看懂 Root 在做什么、计划到了哪里，而不是阅读实现者的原始细节。ELI5 不是真的把用户当五岁小孩。
- **来源：** `SKILL.md`“先确定受众和用途”“分两层解释”；2026-08 用户关于 Claude Code ELI5 思想的说明。
- **验证：** 静态结构和短探针通过；真实长任务持续可读性待验证。
- **改变条件：** 用户指定年龄、专业背景或角色时按实际受众调整。

## E-02 复杂计划和阶段报告视觉优先

- **状态：** `current-effective + unverified`
- **行为：** 流程、层级、因果、路线和当前位置用一张主要图先建立全局，再用少量文字说明变化、结果、缺口和下一步；普通短进度不为了形式制图。
- **理由：** 大量文字和 Agent 报告会让非实现者失去全局。Mermaid、HTML 或其他图像能让用户更轻松地理解任务结构和当前位置。
- **来源：** `SKILL.md`“视觉优先”；Root Base“过程交流”；`subagent-architecture/rule-rationale.md` R27、R30。
- **验证：** 规则存在；真实长任务图是否持续可读尚未验收。
- **改变条件：** 可视化没有明显优于短段落时直接用文字；一张图只承载一个主要心智模型。

## E-03 视觉报告由 Root 形成，subagent 只交证据

- **状态：** `current-effective`
- **行为：** 下属返回结果、证据和限制，Root 根据整体任务形成用户可读的图和解释，不把原始报告拼接给用户。
- **理由：** 只有 Root 保留完整任务框架和用户理解，subagent 无法可靠解释跨阶段位置。
- **来源：** `SKILL.md`；Root Base；Agent 责任链。
- **验证：** 静态责任清楚；真实阶段报告待验证。
- **改变条件：** 独立小任务由当前 Root 自己形成报告，不为此增加阶段层级。

## E-04 图和简单语言不替代完成证据

- **状态：** `current-effective`
- **行为：** 事实、推断和未知分开；不能为了易懂删除会改变决定的前提、风险、边界和不确定性，也不能让漂亮图表证明任务完成。
- **理由：** 视觉是降低理解成本的载体，不是把局部进度包装成成功。
- **案例：** C-14。
- **来源：** `SKILL.md`“保持准确”；全局验证责任。
- **验证：** 静态规则明确。
- **改变条件：** 可以减少术语和背景，但不能改变证据层或结论强度。

## E-05 语言随受众变化

- **状态：** `current-effective`
- **行为：** 儿童用短句和熟悉类比；管理者重结果、风险和成本；工程师保留标准机制术语。默认用户是需要全局理解的成年负责人。
- **理由：** 同一种“简单”对不同受众会失真，过度幼儿化和术语堆砌都增加理解成本。
- **来源：** `SKILL.md`“根据受众调整”。
- **验证：** 静态原则明确；不同受众案例仍可补充。
- **改变条件：** 用户明确要求另一种解释风格时以用户要求为准。

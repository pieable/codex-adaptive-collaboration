# 代码与成熟方案来源表

代码联网搜索的首要用途是少写不必要的新代码。先从本地项目确认真实需求、技术栈、版本、现有依赖和不能改变的接口，再寻找已经成熟、实际使用过的项目、库或参考实现。官方文档和源码用于核验候选，不应把搜索缩成只查 API。

## 搜索顺序

1. 先检查当前仓库有没有相同功能、可复用模块或已经安装的依赖。
2. 检查语言标准库、框架原生能力和平台官方组件。
3. 从官方包注册表、项目组织、代码托管平台和可靠的生态目录列出成熟候选。不要找到第一个能运行的项目就停止。
4. 打开候选的源码、文档、测试、发行记录、问题区和许可证，判断它是否真的适合当前版本和接口。
5. 优先直接使用成熟依赖；不适合整体引入时，学习它已经验证过的设计或移植最小部分。复制源码前确认许可证、归属说明和安全边界。
6. 只有现成方案不适配、引入成本过高或存在明确缺口时，才写最小的新实现，并说明为什么没有采用候选。

候选范围较宽时，先运行：

`python scripts/discover_code_candidates.py --query "<功能描述>" --ecosystem <生态> --output <json路径>`

研究者根据真实需求选择多个简短查询，覆盖用户术语、常用项目术语和关键机制，但不要无目的扩展。GitHub 主查询少于三个结果时，程序会机械地把有效关键词合成一次较宽的 `OR` 查询补搜，并在 `coverage.search_attempts` 中保留两次实际查询；它不理解查询含义，补搜结果需要研究者检查相关性，也不能证明结果已经完整。先检查输出的 `coverage`，再从 `candidates` 选择少量项目深入核验。程序支持 GitHub、npm、crates.io、pkg.go.dev 和 NuGet 的公开查询入口；Python使用GitHub发现项目，并用PyPI单项目JSON接口核验同名候选。PyPI没有受支持的关键词搜索API，因此这一路径不能声称遍历了全部Python包。

## 去哪里找

| 目标 | 候选发现入口 | 核验入口 | 需要回答 |
|---|---|---|---|
| 可直接使用的库或工具 | 对应语言的官方包注册表、GitHub/GitLab项目搜索、维护组织仓库、框架插件目录 | 官方仓库、文档、测试、Releases、依赖和许可证 | 是否覆盖需求；支持哪些版本；是否仍维护；引入和替换成本多大 |
| 可学习的成熟项目 | 同类产品的官方开源仓库、基金会或厂商项目、可靠生态清单 | 架构文档、源码主路径、集成测试、设计讨论、真实部署说明 | 哪个机制解决了同一个问题；哪些约束与当前项目不同；能否只学习局部 |
| 某项能力的多种实现 | 包注册表关键词、GitHub Topics与代码搜索、官方生态目录 | 每个候选的源码、测试、性能和兼容性材料 | 候选集合是否足够；各自取舍是什么；为什么选择或排除 |
| API 当前行为 | 对应版本的官方文档、官方源码和测试 | 官方示例、迁移指南 | 文档与实际版本是否对应；关键行为能否定位到源码或测试 |
| 版本变化或回归 | 官方 release notes、changelog、tag/commit diff | 相关 issue、PR、维护者讨论 | 首次变化版本、具体改动和适用范围是什么 |
| 报错或疑似 Bug | 本地最小复现、上游 issue、源码调用链 | PR、提交记录、维护者回复 | 是使用错误、已知缺陷、已修复还是未确认 |
| 安全问题 | 厂商公告、GitHub Advisory Database、OSV、语言或系统安全公告 | NVD、CISA KEV | 受影响版本、修复版本和缓解方法是否相互对应 |
| 协议与标准 | 标准机构的正式规范和勘误 | 官方参考实现、兼容性测试 | 具体版本和条款是什么；成熟项目怎样实现它 |

## 判断一个项目是否值得采用

- 功能适配：它解决的是不是同一个问题，能否保留当前接口和关键行为。
- 成熟程度：发行历史、最近维护、测试、文档、实际用户和生产使用证据。Star、下载量和搜索排名只能作线索，不能单独证明质量。
- 集成成本：新增依赖数量、运行环境、二进制体积、初始化和迁移工作、后续升级负担。
- 风险：许可证、供应链、安全公告、已知缺陷、单一维护者、平台和版本限制。
- 可验证性：当前项目能否用小型原型或现有测试确认它确实适用。

交回结果时列出真正有竞争力的候选、直接链接、成熟度与适配证据、采用方式和排除理由。候选很多时先按硬条件淘汰，再深入少量候选；不要把十几个项目名称交给主任务自己重查。

## 常用入口

- 通用：项目或维护组织的官方仓库、GitHub/GitLab搜索、Releases、Tags、Issues、Pull Requests、许可证和依赖清单。Awesome列表、博客和问答只用来发现候选。
- Python：`pypi.org`、`docs.python.org`、`peps.python.org`、`github.com/python/cpython`。
- JavaScript / Node.js：`npmjs.com`、`registry.npmjs.org`、`nodejs.org/docs`、`github.com/nodejs/node`、`tc39.es`。
- Rust：`crates.io`、`docs.rs`、`lib.rs`、`doc.rust-lang.org`、`github.com/rust-lang/rust`、`rustsec.org/advisories`。
- Go：`pkg.go.dev`、`proxy.golang.org`、`go.dev/doc`、`github.com/golang/go`、`vuln.go.dev`。
- Web 平台：框架官方生态目录、WHATWG、W3C、ECMA、Web Platform Tests；MDN适合导航，关键行为回到标准原文。
- Microsoft / Windows / .NET：NuGet、`learn.microsoft.com`、对应的 Microsoft GitHub组织、产品 release notes 和安全响应中心。
- Linux与发行版：kernel.org、项目或发行版官方包仓库、源码、文档和安全公告。
- 漏洞聚合：`github.com/advisories`、`osv.dev`、NVD、CISA KEV。最后回到厂商或上游公告核对。

Stack Overflow、论坛、博客、排行榜和搜索摘要可以提供关键词、经验和未知入口；除非问题本身问的是社区实际经验，否则不把它们作为关键技术结论或项目成熟度的唯一证据。

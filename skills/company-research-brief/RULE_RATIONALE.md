# `company-research-brief` 规则理由

本文件不参与运行。当前版本为 2026-08-30 重新定义稿，服务用户的风投同事。旧安装目录的多轮备份作为历史证据保留，不把已撤回的固定字数、固定标题、强制 report-writer、DeepSeek 润色和固定 Word 样式自动恢复。修改正文时同时读取 `references/eval-cases.md`，用真实失败边界检查候选，而不是把理由文字当成自动正确的结论。

## CRB-01 研究由实际决定驱动

- **状态：** `current-effective`
- **行为：** 先确定读者要作出的决定，再选择资料补全、快速初筛、投前简报、专题研究或市场测算的交付口径。
- **理由：** 同一批公司材料用于“了解事实”和“是否继续尽调”时，需要的结论强度不同。先确定决定可以避免机械写一份看似完整但不能支持行动的通用报告。
- **案例：** WorkBuddy 投研任务中，用户明确纠正“候选发现不是主体，核心是产品线比较、投前判断和报告”。
- **来源：** 旧 `SKILL.md` 模式路由；memory rollout `2026-08-26T13-17-09-Flme...`；本轮用户说明。
- **验证：** 真实业务用途已确认；新稿尚未完成风投同事真实任务测试。
- **改变条件：** 只有 Skill 被拆成用途完全不同的独立 Skill 时才改变入口路由。

## CRB-02 公司判断以产品线和商业化阶段为单位

- **状态：** `current-effective`
- **行为：** 多业务公司拆产品线和收入主线，分别识别客户、应用、阶段与比较对象；同业关系不是永久公司标签。
- **理由：** 公司层面的“同行”会把不同产品、应用和商业阶段混在一起，导致错误比较。投资判断需要知道具体哪条产品线在产生客户、订单、收入和回款。
- **案例：** 企业投研历史要求按产品线区分直接竞品、替代、成熟标杆和上下游参照。
- **来源：** memory rollout `2026-07-30T15-54-49-eMdm...`；用户过去投研校准。
- **验证：** 历史真实报告支持；新 Skill 行为未前向测试。
- **改变条件：** 公司只有单一业务时可以简化，但仍要按具体产品和客户场景判断。

## CRB-03 证据层级限制结论强度

- **状态：** `current-effective`
- **行为：** 分开已核验事实、公司自述、第三方线索、推断和尚需核验；重要商业化主张使用与其风险相称的来源。
- **理由：** BP、官网和创始人材料有明确传播目的，能证明公司主张但不能自动证明客户、订单、收入、领先或市场份额。若不分层，报告会把营销信息升级成投资事实。
- **案例：** 历史公司研究多次需要把“已导入头部客户”“领先”和大市场主张降回公司自述或待核验。
- **来源：** `references/source-policy.md`；旧 Skill 2026-06 至 08 月持续保留的证据边界。
- **验证：** 规则和真实使用反例明确；具体来源仍按任务核验。
- **改变条件：** 新证据足以验证主张时可以升级，并保留来源和时点。

## CRB-04 搜索围绕会改变判断的问题并在边际收益下降时停止

- **状态：** `current-effective`
- **行为：** 把公司位置、阶段、比较、市场、风险和结论缺口转成检索问题；新增资料很少改变这些判断时停止扩大。
- **理由：** 固定清单会在材料充分时浪费时间，也会在真正关键的未知尚未回答时制造“已经搜完”的错觉。搜索的价值是改变下一步，不是积累链接数量。
- **案例：** C-13；半导体来源实验发现工具成功不等于候选覆盖充分。
- **来源：** 旧 `SKILL.md` 工作流；`deep-research`；`search-source-registry`。
- **验证：** 搜索机制反例明确；不同公司停止点仍需人工判断。
- **改变条件：** 法规、审计或用户要求固定覆盖清单时，完整性本身成为验收条件。

## CRB-05 比较对象分为直接竞品、替代、成熟标杆和上下游参照

- **状态：** `current-effective`
- **行为：** 先解释比较关系，再使用对客户选择和商业化阶段有意义的维度比较。
- **理由：** 只有直接竞品会漏掉客户真正采用的替代路线；把成熟标杆和上下游公司都叫竞品，又会产生虚假胜负。分类让每类参照回答不同问题。
- **案例：** 企业投研历史中的产品线比较要求。
- **来源：** memory rollout `2026-07-30T15-54-49-eMdm...`；`references/industry-analysis-framework.md`。
- **验证：** 真实工作流已出现；当前 reference 仍需随新稿复审措辞。
- **改变条件：** 当前决定只需要一种关系时不为完整感展开其他类别。

## CRB-06 市场规模必须连接到公司现实机会

- **状态：** `current-effective`
- **行为：** 区分大行业背景、产品品类、应用细分、目标产品机会和公司现实可进入部分；估算写清公式、口径、假设和敏感项。
- **理由：** 大行业增长不等于目标公司的订单或收入。采购预算、认证、价格、渠道、产能和交付共同决定需求能否传到公司。
- **案例：** 历史报告反复纠正用宽泛赛道规模代替公司机会。
- **来源：** `references/market-sizing-guide.md`。
- **验证：** 方法静态明确；每次测算需要单独验证数据和假设。
- **改变条件：** 用户只要行业背景时可以不做公司机会测算，但要说明数字解释到哪一层。

## CRB-07 只有用户要求时才给投资处理意见

- **状态：** `current-effective`
- **行为：** 初筛和投前任务给当前处理意见；信息整理保持中性。缺资料既不自动否定，也不自动接受公司主张。
- **理由：** 研究者不能在用户只要事实时擅自扩大成投资建议；反过来，用户明确要“是否继续看”时只罗列资料又没有完成任务。
- **案例：** 旧 Skill 长期区分信息搜集版与投前判断版。
- **来源：** `references/investment-judgment-framework.md`；用户业务用途。
- **验证：** 当前路由明确；结论标签的真实使用体验待复测。
- **改变条件：** 用户指定其他决策尺度或不需要标签时按用户场景表达。

## CRB-08 后台研究材料与前台报告分开

- **状态：** `current-effective`
- **行为：** 正文只写读者需要的事实、比较、风险和判断；搜索过程、台账、补证清单、证据标签和工具协作留在验证材料。
- **理由：** 投资同事需要快速理解公司，而不是阅读 Codex 的工作过程。后台材料仍需保存，以便追溯来源和检查结论。
- **案例：** 旧版本曾把“证据缺口、补证、判断强度”等内部词带进老板版正文，随后多轮修正。
- **来源：** `references/report-structure.md`；历史 `teacher-report-shape`、`frontstage-headings`、`no-footer` 等备份。
- **验证：** 多轮用户校准支持；新稿成品仍需真实报告测试。
- **改变条件：** 交付物本身就是审计底稿或真实性验证文档时可以展示后台结构。

## CRB-09 Word 是按需交付，不是默认主流程

- **状态：** `current-effective`
- **行为：** 先完成可靠正文和来源映射，用户需要正式文档时再生成 Word 并做一致性检查。
- **理由：** 固定字体、标题数量和 Word 路线曾让格式压过研究判断；但正式投前材料仍可能需要可直接流转的 Word。按需生成同时保护内容和使用场景。
- **案例：** 历史 `word-format`、`report-writer` 多轮版本已被当前简单样式取代。
- **来源：** 旧安装备份；`references/report-structure.md`；用户历史工作流。
- **验证：** 文档工具链可用性按宿主验证；本 Skill 不自带 Word 脚本。
- **改变条件：** 目标团队固定使用其他交付系统时替换相应格式，不改变事实一致性要求。

## CRB-10 References 只在相关分支读取

- **状态：** `current-effective`
- **行为：** `SKILL.md` 保留共同决策和路由；来源、市场、比较、判断和成文细节按任务读取对应 reference。
- **理由：** 公司研究跨度大，把所有细则放进入口会增加每次调用成本并迫使简单初筛扫描无关方法。渐进披露让短任务保持便宜，也保留复杂任务需要的专业细节。
- **案例：** 旧 Skill 114 行仍重复多个 reference 内容；本轮重写把模式细节和方法说明重新归位。
- **来源：** `skill-creator` 的 progressive disclosure 原则；本轮重写。
- **验证：** 静态路由可检查；真实调用是否读对 reference 尚未验证。
- **改变条件：** 某项 reference 内容变成所有公司任务都必须知道的共同边界时迁回入口。

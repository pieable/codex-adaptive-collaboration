# 市场判断指南

本文件用于形成市场底稿和验证文档，不直接决定正文措辞。正文语言遵循 `references/report-structure.md` 的正文语言标准。

## 1. 市场数字先分层

任何市场数字都先判断它解释的是哪类问题：

1. 宽泛行业背景：说明一个大行业或主题的发展环境。
2. 产品或服务品类：说明某类产品、材料、设备、软件或服务的总体需求。
3. 应用细分场景：说明特定客户、行业、地区或应用里的需求。
4. 目标产品相关机会：说明公司具体产品或服务可能对应的收入机会。
5. 公司现实可进入的机会：受地区、客户类型、价格带、渠道、资质、认证、产能和交付能力影响的部分。

分层用于内部判断和验证文档。写正文时，把分类结果改写成具体事实和约束条件，不把分类名直接写成报告语言。

市场段落优先写清三件事：

- 这个数字具体覆盖什么。
- 它和公司产品、客户预算或采购场景有什么关系。
- 它不能说明什么。

## 2. 需求传导

市场章节不只写规模数字，还要说明需求怎样传到公司产品。

底稿中回答：

- 下游应用或客户需求为什么变化。
- 谁采购、谁使用、谁决策。
- 采购预算来自哪里。
- 目标产品在客户方案中承担什么作用。
- 下游增长会如何影响目标产品用量、单价、采购意愿或替换节奏。
- 这条传导关系是直接、间接，还是目前证据不足。

正文中用自然语言解释这条关系。传导关系不清时，把相关市场写成行业背景，而不是写成公司机会。

## 3. 市场数字记录

每个市场数字都记录：

- 发布机构。
- 发布日期。
- 地理范围。
- 时间区间。
- 市场定义。
- 币种和汇率口径，如发生换算。
- 数字包含的收入类型：产品、服务、交易额、软件订阅、广告、金融收益、材料、设备或其他。
- 与目标公司产品的关系：直接相关、间接相关、背景参考或待确认。

这些信息进入真实性验证文档。正文只保留读者理解市场判断所需的口径说明。

## 4. TAM/SAM/SOM

只有在用户要求市场空间测算、融资材料、投资判断或商业计划时，才使用 TAM/SAM/SOM。

使用时先说明假设：

- TAM：理论上解决该问题的总需求。
- SAM：公司产品现实可服务的市场。
- SOM：公司在一定时期内可能获得的份额。

数据不足时，可以用自下而上方法估算：

`目标客户数量 x 渗透率或项目数量 x 单客年支出/客单价 x 复购或替换周期`

对交易平台，可用：

`交易用户数 x 交易频次 x 客单价 x 抽佣率`

对订阅或企业服务，可用：

`目标客户数 x 付费转化率 x 年合同额 x 续约率`

这类结果是基于明确假设的市场估算，不等于公司已经获得的客户机会、订单或收入。正文应把估算值与已核验经营数据分开表达。

正文中不要为了显得完整而机械展示 TAM/SAM/SOM。只有测算本身服务任务目的时才写。

## 5. 采用节奏

存在市场需求不等于短期收入可实现。需要检查：

- 客户决策和采购周期。
- 切换成本和组织阻力。
- 渠道建设时间。
- 价格接受度和付款周期。
- 现有供应商、品牌或平台锁定效应。
- 合规、资质、交付、售后或生态支持要求。

正文要说明这些因素如何影响公司把市场需求转成订单、收入或客户导入。

## 6. 常见偏差

市场判断优先避免三类问题：

- 用大行业规模代替公司产品机会。
- 只写市场增长，不写谁采购和为什么采购。
- 把客户认证、产能、交付、渠道或价格限制忽略掉。

修正方式是回到问题：这个市场数字到底解释什么？它和公司产品、客户预算、商业化阶段之间是什么关系？

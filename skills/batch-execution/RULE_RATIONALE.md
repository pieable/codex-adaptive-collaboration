# `batch-execution` 规则理由

本文件不参与运行。

## BE-01 只在错误会扩散的批量阶段使用

- **状态：** `current-effective`
- **行为：** 大量相似对象、单次错误会扩散、成本高或难回滚时使用；短解释、单文件稳定修改和可立即完整验收的小任务直接做。
- **理由：** 小样和恢复账本本身有成本，不应给所有简单任务增加流程。
- **来源：** `SKILL.md` description 和开头；初始 Git 历史。
- **验证：** 触发边界静态明确；跨任务准确率待观察。
- **改变条件：** 以错误扩散和回滚代价判断，不按文件数量机械触发。

## BE-02 扩大前先固定整批边界和恢复方式

- **状态：** `current-effective`
- **行为：** 写清对象、允许变化、保持项、验收方式以及处理中断后的识别和恢复；外部写入、付费、覆盖或难撤销操作准备副本、事务或幂等标识。
- **理由：** 批量最危险的是错误范围和半完成状态无法区分，单项成功无法弥补整批不可恢复。
- **来源：** `SKILL.md`“先确定整批边界”；全局 Windows 文件安全。
- **验证：** 静态规则存在；真实恢复演练未统一记录。
- **改变条件：** 操作天然只读、幂等且可完整重跑时可简化恢复材料。

## BE-03 小样覆盖最可能失败的处理路径

- **状态：** `current-effective`
- **行为：** 选择最长、复杂、边界、真实依赖或跨模块关键对象；不同处理路径至少覆盖一个代表样本，不按固定数量抽取。
- **理由：** 只选最短最整齐对象会产生虚假信心；小样价值取决于能否暴露方法和验收问题。
- **案例：** C-22 提醒测试必须对应真实入口；Spark 机械转换曾漏字段。
- **来源：** `SKILL.md`“选择能够暴露失败的小样”；`subagent-architecture/rule-rationale.md` R10。
- **验证：** 原理和历史反例支持；具体小样按批次判断。
- **改变条件：** 所有对象确实走同一受验证路径时可以缩小样本。

## BE-04 小样通过只证明已覆盖路径

- **状态：** `current-effective`
- **行为：** 检查内容、格式、外部状态、成本和错误处理；主观或不可逆结果由用户验收，明确可机械判断的结果可自动验收。新对象类型先补小样再扩大。
- **理由：** 一个样本成功不能证明不同结构、权限和输出类型都安全。
- **来源：** `SKILL.md`“验收后再扩大”；全局验证责任。
- **验证：** 静态规则明确。
- **改变条件：** schema 或处理路径能证明全体同构时，可以自动覆盖更多对象，但声明需匹配证据。

## BE-05 执行分片交便宜角色，整体风险留给负责人

- **状态：** `current-effective + unverified`
- **行为：** 主任务或阶段负责人掌握整批边界、小样和总验收；可独立验收的分片通常交 Worker Luna，Spark 只在额度和速度收益成立时使用；合同包含成功、失败、跳过、停止和恢复定义。
- **理由：** 机械批量适合便宜模型，但跨分片覆盖、重叠和恢复不能由单个 worker 判断。
- **案例：** 固定合同的 Spark 成功与开放诊断漏项。
- **来源：** Git `f6d8ab0`；`SKILL.md`“交接到执行者”；Agent 成本体系。
- **验证：** 静态编排明确；真实大批量成本收益待验收。
- **改变条件：** 角色价格和能力改变时可更换执行者，整体所有权不下放。

## BE-06 出现未覆盖类型或连续偏差时停止扩大

- **状态：** `current-effective`
- **行为：** 新结构、连续失败、结果偏离、成本超估或无法区分处理状态时保留已完成结果并停止，由整体负责人决定补样、改法或终止。
- **理由：** 批量错误继续扩大只会增加清理成本；停止条件必须早于整批完成。
- **来源：** `SKILL.md`“执行整批并及时停止”；全局动作门。
- **验证：** 静态规则存在；真实停止/恢复路径待验证。
- **改变条件：** 不得因“已经做了很多”继续；只有新证据证明方法恢复可靠才重新扩大。

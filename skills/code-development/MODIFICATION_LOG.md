# Code Development Skill 修改记录

这份文件不参与 Skill 运行。它保存规则为什么存在，帮助以后修改时保留已经验证有价值的行为。

## 2026-08-25 恢复最低复杂度的代码细则

用户在重写 Base 时确认，跨任务的共同原则只需要要求复用现有能力、选择满足当前结果的最低复杂度，并保持局部修改的范围。代码实现中的具体做法由本 Skill 承载。

本次恢复的语义来自用户提供的网上流出的 Claude Code 提示词摘录。来源没有在本次修改中独立核实，因此只作为来路说明。用户已经确认这些规则符合自己的长期代码工作经验。

运行正文现在要求一次性操作直接实现，几行相似代码优先于过早抽象。内部代码和框架已有明确保证时直接依赖，把校验放在真实系统边界。局部修复只覆盖当前结果，不顺手扩成周边清理、额外配置或未来设计。确认失效的代码直接删除，不留下没有实际用途的兼容痕迹。

这些规则保留当前合同明确要求的兼容性、安全、数据保护、信任边界和可访问性。它们约束过度工程化，不削弱真实边界或用户要求。

文字已经静态复审。真实代码任务中的行为效果尚未验证。

## 2026-08-27 调整阶段内回报和角色路由

两个新 Base 任务中，Root 虽然把执行交给 subagent，仍直接创建和管理大量调查、实现、评审、浏览器与验证责任，并通过密集的 followup、send 和 wait 跟进。Sol、Terra 和 Luna 的模型回合因此处于相近数量级。问题不是角色分工缺失，而是阶段内结果持续回到 Root，阶段负责人没有完整吸收下属报告、返工和验收。

本次保留简单责任直接交给执行角色、复杂模块交给 `code-executor` 的分工。阶段预计需要多个下属或多轮调整时，由阶段负责人直接管理并向上级交回一份阶段结果。实现已有阶段负责人时，评审、返工和重新验证也回到该负责人。执行角色的具体选择改由当前注册的角色说明提供，本 Skill 不再复制本地取证、网络取证、浏览器和 Worker 的角色表。

同一责任继续、创建新责任和等待的固定动作已经由全局 `AGENTS.md` 直接绑定到 collaboration 工具，角色提示词不再重复轮询和等待过程。文字、TOML 和公开副本完成静态验证。新建 `worker-luna` 已确认实际加载共同执行层。Root 调用是否下降仍需在后续真实任务中统计。

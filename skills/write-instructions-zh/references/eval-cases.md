# 提示词与规则编写评测案例

这些案例只用于维护或重写 `write-instructions-zh`，普通提示词任务不加载。评测关注目标模型从目标使用时稳定获得的指令链和信息来源中会形成什么判断和行动，不按字数、否定句数量或结构整齐程度评分。

## 通过标准

- 能从用户的选择、纠正和当前系统恢复愿景，而不是只执行最近一句。
- 删除或迁移规则后，原有判断、取舍、权限和效果仍被正确承载。
- 按责任、直接证据、决策权和稳定信息链分配判断；层级负责协调，不压过直接证据。
- 模型专项检查处理执笔模型经过反复纠正仍容易复发的倾向。GPT-5.6 专项逐句检查防御性否定和枚举。防御性否定只保护正向规则仍会遗漏的明确边界或具体高代价失败。同类内容默认归纳为共同原则，模型需要按项查找、执行或核对时再枚举。
- 生效文本只包含当前指导；演变原因和已废弃路线留在历史材料。
- 复审目标使用时稳定获得的 Base、角色提示词、Skill、合同和配置，不用当前修改会话补足未来缺口。
- 区分文件写入、静态有效、宿主加载和真实行为验证。
- 标题、段落、无序列表、有序列表和嵌套列表表达真实语义关系，不把示例层级当作固定模板。
- 保真并集中标为当前的规则，由生效正文直接承载，或者有可核验的等价吸收关系；不能只因新文本更短、更整齐就判定保真。

## 案例一：从多轮纠正恢复整体愿景

用户先要求精简子代理规则，随后指出删掉了上下文隔离、工人局部判断、阶段负责人继续派工和主任务直派中等任务的能力。

期望：先恢复这些选择共同服务的工作结构，再重写连贯的当前规则；不能把四句反馈逐条追加成修改日志式禁令。

## 案例二：判断权随责任分布

一个 `explorer` 需要从大量原始资料中筛出会改变上级结论的证据，但不能决定用户的整体路线。

期望：允许它判断相关性、证据强弱和合同覆盖，同时把用户意图、跨阶段取舍和最终结论留给拥有完整上下文的责任人。下级用证据报告矛盾但不自行夺取整体任务，上级必须处理证据而不能凭印象否定；不能把证据强度和裁决权写成简单高低排序，也不能擅自增加用户没有确认的争议轮数、上报次数或固定流程。

## 案例三：正向机制与必要边界

候选提示词已经说明“执行者按合同完成固定责任并上交证据”；历史上仍多次出现执行者越权改变授权范围。

期望：保留正向合同机制，并加入只针对权限扩大的明确边界。不能机械删除所有否定句，也不能把每次普通执行差异写成禁令。

## 案例四：权威迁移而非重复复制

一条角色专属行为原来同时写在 root Base 和角色提示词中；当前宿主确认该角色总会加载自己的提示词，但 root 不需要据此调度。

期望：把具体行为保留在角色提示词，root Base 只保留调度所需的接口；确认所有目标阅读者都能获得新来源后再删除重复。不能仅因文字相似就合并，也不能为保险永久复制两份。

## 案例五：Skill 的语义与结构共同修改

用户要求修改一个 Skill 的职责，同时新增按需参考资料和前向测试。

期望：使用本 Skill 恢复愿景、判断权和语义边界，使用 `skill-creator` 处理触发、资源组织、元数据和静态校验，并复审最终加载组合。不能让任一 Skill 代替另一方的职责。

## 案例六：生效规则与演变记录分离

历史上某条严格禁令是为修复已经不存在的平台缺陷而加入；新的正向机制已覆盖仍有效的风险。

期望：当前提示词只保留仍会改变行为的机制，旧禁令及其来源进入版本或演变记录。不能为了展示审慎而把过时事故继续写进生效文本。

## 案例七：稳定信息链中的空洞

root 加载了批处理 Skill，但 worker 的配置关闭 Skill 自动注入；root 的委派合同只写“按批处理 Skill 工作”。

期望：识别真实加载链中的空洞，在 Base、角色或合同接口的适当层补上传递机制，而不是把完整 Skill 复制到每个角色，也不能假定 root 已加载就等于下属已获得。

## 案例八：字面覆盖但真实行为没有触发

一条 Base 已经写着“路线证据不足时不扩大投入”，但一次真实高代价任务仍在未经代表性验证的路线中持续实现和评审，最后没有形成可用结果。

期望：不能只因文字相近就判断“规则已经覆盖，不改提示词”。应检查这条规则在稳定指令链中的位置、注意力竞争、相邻规则冲突、责任接口和真实传递，再决定重组、提高作用、修改其他来源或确认问题不在提示词；用户对跨任务代价和结果的说明是强证据，模型提出的技术原因仍须核实。

## 案例九：规则与直接对话例子并存

一个长期角色提示词同时包含明确责任边界和多轮真实对话例子；例子用于校准关系、语气和反应方式，无法被几条抽象形容词等价替代。

期望：保留仍会改变体验的少量差异化例子，并以明确规则处理责任和边界；不能因为例子不增加显式事实就全部删除，也不能把例子中的醒目措辞提炼成普遍口号。规则与例子冲突时，以明确规则和边界为准。

## 案例十：结构方向不是固定模板

用户要求提示词更加结构化，给出多级标题作为方向示例，随后说明标题应尽量表达单一概念，但内容太短时没有必要单独分块。

期望：根据稳定主题、内容独立性和阅读定位决定章节。标题使用自然语言直接说明本节讲什么，使第一次阅读者只看目录就能判断其中的对象、情境或责任；不为简短、等长或形式统一压成无法定位内容的宽泛分类词。段落表达连续关系，无序列表表达并列规则，有序列表只表达真实步骤、阶段、优先级或判断顺序，嵌套列表表达从属关系。调查时需要共同考虑的因素不是天然的执行顺序，不应只因可以编号就改成固定流程。不能照抄示例的层级深度，不能为了标题单一而制造只有几句话的小节，也不能把原本独立的规则用复合标题和分号重新压在一起。

## 案例十一：结构重写后的保真核对

一个成熟 Skill 已有规则储藏库和标注状态的保真并集。候选版本保留了原有标题方向并明显缩短正文，但压弱了直接证据与裁决责任、字面覆盖失效时的诊断、新建提示词的最小当前版本、例子保护、语义等价检查、Git 保护和分层验证。

期望：逐项核对保真并集中的当前规则，确认候选正文直接承载相同行为，或者存在明确且可验证的等价吸收关系；恢复会改变判断和行动的缺失机制。不能把主题相近、宽泛名词、较少项目或更整齐的目录当成语义等价，也不能为了恢复旧规则而机械复制旧结构和旧措辞。

## 案例十二：成熟提示词的局部修改

用户只指出成熟 Base 中一项委派责任存在问题。候选方案为了让全文更连贯，重新生成所有章节，并声称新版本整体表达了相同意思。

期望：默认保留没有问题证据的原文和措辞，只修改会形成目标行为所需的局部机制。只有确认累积补丁已经破坏整体关系时才重组，并在重组前后逐项映射原有规则承担的行为。不能把“不机械打补丁”解释成整体重写，也不能用模型自己的概括证明语义保真。

## 案例十三：模型迭代中的骨干和血肉

一个成熟 Base 同时包含跨模型仍应成立的工作方法，以及为了当前模型、宿主和工具形成正确行为而加入的具体说明、例子和固定协议。候选精简把前者压成抽象短句，又把见过的失败逐项写成清单。

期望：从目的、背景、行动、结果和边界中选择实际需要的内容，恢复需要跨版本保持的骨干，把当前模型才需要的内容作为血肉贴在骨干上。模型或宿主变化时先保持骨干，再复审血肉。以跨版本行为是否一致判断修改，而不以新文本是否更短、更连贯判断。开放现实使用能够迁移的原则，模型需要按项查找、执行或核对时再枚举。

## 案例十四：减少条目没有消除枚举

候选版本把一组较长的场景或判断因素缩成两三个代表词，并据此认定已经完成反枚举审查。目标模型仍需逐项理解这些词，再自行推断它们共同控制什么判断。

期望：先找出这些项目共同影响的判断关系。一个关系能够覆盖整组内容时，直接写清这个关系怎样改变行动，整组项目消失。每项都会独立改变行动，或者模型必须分别处理时，才逐项保留。形式上的缩短不能证明枚举已经消除。

## 案例十五：提炼后只剩抽象词

候选版本为了消除枚举，把一段能够直接指导行动的说明改成“调查问题空间”“控制实际影响”或其他宽泛概括。第一次阅读的模型知道这些词大致正确，却无法从文字本身判断具体何时怎么做。

期望：共同原则既能覆盖未列情境，也要直接说明它怎样改变行动。概括词仍需读者自行补全含义时，恢复足以形成行动的具体说明。必要差异会分别改变行为时直接保留，不能为了文本更短而强行合并。

## 前向测试方法

1. 在独立上下文中提供待测提示词体系和一个真实请求，不提供本文件中的期望文字。
2. 要求模型说明它识别的用户愿景、责任与直接证据分布、稳定信息来源、拟修改位置和验收层次，再产出修改候选。
3. 检查删除、合并和迁移是否保持原有行为，新增边界是否对应具体失败机制。
4. 至少加入一个未写入本文件的留出案例，并分别测试简单单文件提示词和多层组合体系。
5. 每轮只改变一组相关规则，保持模型、推理档位和测试请求不变，再比较行为差异。

# 提示词与规则编写

## 目标

把提示词写成能让有充分理解能力的模型还原用户愿景，并在未列情境中作出一致判断的当前指导。默认模型已经具备通用的理解、规划和表达能力；只写它不能从实际任务、完整注入上下文、工具和常识中可靠推导，或者值得长期占用注意力的信息。

提示词的质量取决于目标模型读完实际组合后的上下文会形成什么判断、采取什么行动，以及用户最终得到什么效果，不取决于文件长度。精简是保真重写；只有删除后仍能保持原有判断、取舍、边界和效果，才算真正精简。重要提示词和长期规则的愿景还原、证据取舍、编写与语义复审由对最终结果负责的模型连续掌握；格式处理、固定映射和已经确定内容的同步可以按当前调度规则委派，但不能让转述代替语义判断。

## 恢复模型需要形成的判断

目的、背景、行动、结果和边界共同描述用户希望模型怎样工作：

- **目的：** 为什么做、最终要保护什么，发生取舍时优先什么。
- **背景：** 模型作出判断所需的现实情况和已经形成的理解。
- **行动：** 模型要做什么；方法、工具或顺序只有在会改变结果时才规定。
- **结果：** 用户应当得到的完成状态和相应证据。
- **边界：** 必须保持的内容、权限、风险护栏和停止条件。

这五项是理解提示词的语义视角，不是要求每份提示词套用的格式。简单指令可能只需要一个动作；复杂、长期或经过多轮校准的规则，应让第一次阅读的模型知道要实现什么、为什么、怎样才算完成，以及变化不能越过哪里。

对于无法穷尽的现实情境，传递能够生成判断的机制，不把已经见过的情况写成适用条件。抽象原则需要校准时，用少量具有差异的例子展示原则怎样作用，使模型能够把共同关系迁移到未列情境；例子不是完整分类、触发清单或适用范围。需要模型迁移判断的内容用原则和例子，需要模型准确知道的封闭事实和机制直接明确规定。例如固定字段映射、准确的工具协议和权限边界不能靠类推补全。不能用减少项目数量、压成密集句子或换成宽泛名词冒充提取原则。

## 放在权威层级

把规则放在最接近其权威来源、又能覆盖全部目标阅读者的位置；部署位置受宿主限制时，仍按规则的真实职责理解，不因文件放在哪里而改变适用范围，也不在多个层级重复保存同一要求。例如角色自己的行为由角色提示词负责，项目事实和项目工作方式留在项目层，会变化的配置事实靠近当前配置来源。

创建或修改 Skill 时，同时使用当前 `skill-creator` 处理触发、目录结构、资源和静态校验；本 Skill 负责愿景还原、语义取舍和保真复审，不复制可能随平台变化的 Skill 结构说明。成熟 Skill 以长期稳定的目的、工作主干和完成方向为骨架；仍需每次触发时影响行为的具体规则直接保留，按需材料和确定性资源才放入 `references/`、脚本或资产。依赖发生变化后先检查骨架是否仍成立，再局部调整附着规则，不因一个局部变化重写全部内容。

## 编写与修改

开始前确认权威文件、目标阅读模型、实际注入上下文和版本状态，弄清用户愿景、本次范围、现有正确效果与必须保留的边界。先验证问题是否真的来自提示词；加载机制、外部事实或执行过程的问题应修正其真实来源，不向提示词增加补丁。

新建提示词时，从真实用途和代表性例子恢复模型需要形成的判断，直接写出最小完整的当前版本，不为不存在的历史或假想未来增加结构。修改、精简或恢复成熟提示词时，先确定这次要改变什么，再读取当前文本和会影响该判断的演变记录；只有信息仍不足时才查旧版、备份、会话证据或校准材料。历史用于理解设计目的，不使旧文字和旧路线永久有效。用户没有要求调整、也没有证据表明存在问题的成熟部分，默认保留。

同一问题经过反复增删仍不能稳定解释用户的选择时，先使用 `workflow-state-distiller` 重建当前目的、背景、行动、结果和边界，不再围绕最新一句继续打补丁。

根据恢复出的整体判断起草连贯的当前规则，而不是沿原文逐句删改。主题或措辞相近不代表作用相同；删除、合并或把职责移到别处之前，确认目标模型仍会形成相同的有效判断。只有所有目标阅读者都会稳定获得另一层规则时，当前文件才不再重复它。

规则的明确程度随模型无法可靠推导的程度和错误代价增加。普通且容易纠正的选择可以留给模型；难以言明的体验可以用少量例子校准；脆弱、危险或不可恢复的机制应明确到足以避免错误。规则的适用范围和措辞强度同时服从证据：用户否定某个结果能够证明结果不符合需要，但不能自动证明模型对原因的解释；未经证实的原因不写成确定机制或长期规则。体验校准以真实对话、用户纠正和被接受的样本为依据，不为抽象整齐机械改写。

以正面说明目的、判断原则和期望行动为主；禁令只作为针对反复出现或高代价失败机制的窄边界，不把一次纠正扩张成普遍禁止。未指定的选择不视为禁止，也不扩大明确的权限范围。

## 复审与验证

以第一次阅读的目标模型复审实际组合后的完整注入上下文，而不只检查被修改的文件。确认它能在未列情境和目标冲突中还原用户愿景，保留既有正确效果，并实现本次变化；发现不同表达会改变行为时，保留这种差异，不为表面整齐合并。

验证对应提示词实际承担的风险和证据层。明显的文字、重复和过时事实问题完成静态复审即可；加载、复杂行为或高代价边界是否生效，需要相应层次的验证。文本已经写入、宿主已经加载和真实行为符合预期是不同结论，只声明实际观察到的层次。

## 生效文本与演变记录

生效文档只呈现当前指导。仍会帮助运行模型判断和取舍的原因属于生效指导；只解释某次文字为何变化的历史理由留在版本记录或必要的演变说明中，不把工作过程、日期、哈希和命令堆进提示词。

成熟提示词把生效文本收束为稳定骨架时，在对应的修改日志或专门的演变记录中分开维护规则储藏库和保真并集。规则储藏库保存有助于理解演变和防止错误回流的历代规则、来源与状态，可以包含已经取代、过时、错误或失效的内容；保真并集只保留经核对仍然正确、且当前或在可识别条件下仍可能适用的行为规则，排除过时、错误或失效的规则。两者都不写入生效文本；保真并集中的规则也不表示必须全部在当前生效。未来修改者从保真并集中选择应继续附着或重新加入的规则，并用储藏库核对来源和否决原因。

重要提示词和长期规则默认使用 Git 保存版本。修改前查找覆盖目标文件的现有仓库，不在已有项目中擅自建立嵌套仓库；没有仓库覆盖且管理范围清楚、适合独立保存时，建立仅本地的仓库并提交现有内容作为基线，不配置远程或上传。已有仓库先保留其他改动并确认修改前状态可恢复，修改后查看真实 diff，用说明行为变化的提交保存。Git 只记录建立后的真实历史，不能把旧备份伪造成过去的提交。

Git 已完整保护当前状态时不重复制造普通备份；Git 无法保护本次修改范围时，用只读快照和哈希补足恢复能力。功能块、旧版和演变材料用于理解设计，不要求生效提示词继续保留对应结构。依赖或使用场景变化后，重新判断旧内容是否仍会影响目标模型的必要判断。

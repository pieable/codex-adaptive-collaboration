# 写提示词 Skill 演变记录、规则储藏库与保真并集

这份文件不参与 Skill 运行。`SKILL.md` 是当前生效文本；这里的规则储藏库保存历代会改变行为的规则、来源和当前状态，包括只用于解释演变或防止错误回流的内容。保真并集是从储藏库中筛出的仍然正确、且当前或在可识别条件下仍可能适用的行为规则；过时、错误或失效的规则不属于保真并集。保真并集用于未来修改时选择、恢复和核对，不表示其中规则必须全部复制回 `SKILL.md`。

## 当前愿景

提示词应让有充分理解能力的目标模型从目标使用时稳定获得的指令链和信息来源中还原用户愿景，在未列情境和目标冲突中形成一致判断，并产生用户需要的效果。目的、背景、行动、结果和边界组成跨模型稳定的骨干；当前模型、宿主和工具不能可靠推导的说明、例子和固定协议作为血肉贴在骨干上。精简是保真重写，不以字数减少或新文本自身连贯为成功；历代候选规则留在本记录而不是进入运行文本。

## 2026-08-24 通用结构与正向指导

- 正向指导优先不是本轮新增偏好，而是历代提示词已经形成的原则。本轮把它从“明确程度”的长段落中恢复到显眼位置：正向规则负责说明目标、判断原则和期望行动；禁令只补正向指导不能可靠覆盖，或正向规则下仍反复出现的具体失败机制。风险和错误代价决定规则需要多明确，不构成另一份固定的禁令类别清单。
- 这套结构方法适用于 Base、AGENTS、Agent、Skill 和其他长期提示词，不只适用于较长的综合提示词。
- 标题优先命名一个完整主题，但是否分节还取决于内容是否足以独立展开和是否需要定位。为了消除连接词而制造只有几句话的小节，与把多个独立主题临时粘进复合标题一样，都会削弱结构。
- 标题还必须具有定位作用。第一次阅读者只看目录无法判断本节处理什么对象、情境或责任时，单个宽泛分类词不构成合格标题。标题可以写成“子代理的使用规则”一类自然的说明性短语，不为简短、等长或统一成四字词而牺牲可理解性，也不机械扩成长句。
- 段落表达连续背景、因果、原则和例外。无序列表表达没有顺序的并列规则。有序列表使用 `1.`、`2.`、`3.` 表达真实步骤、阶段、优先级或判断顺序。嵌套列表只表达真实从属关系。
- 用户深度参与编写的一份旧 Base 用作结构尺度样本。它说明章节允许长短不一、列表和段落按语义分工，但其中旧规则不因此自动恢复。
- 已否决两条形式化路线：给每段增加粗体标签不等于结构；照抄用户举例的标题深度并机械拆成多级目录属于过度结构化。结构应使用能够表达真实关系的最浅层级。

## 规则储藏库

状态说明：**当前**表示 `SKILL.md` 直接承载；**已吸收**表示仍然正确的行为已被更一般的当前规则覆盖；**历史候选**表示规则仍然正确，以后可能在可识别条件下重新附着；这三类构成当前保真并集。**已取代**只保存在规则储藏库中，不属于保真并集；规则一旦被确认过时、错误或失效，也应移出保真并集并记录相应状态。

### 目标、责任与保真

- **当前：** 默认目标模型具备通用理解、规划和表达能力，只写它不能从实际任务、完整注入上下文、工具和常识可靠推导，或值得长期占用注意力的信息。
- **当前：** 质量由模型形成的判断、采取的行动和用户得到的效果决定；文件更短不是成功证据，删除后仍保留判断、取舍、边界和效果才是精简。
- **当前：** 愿景还原、证据取舍、编写和语义复审由对最终结果负责的模型连续掌握；格式处理、固定映射和已确定内容的同步可以委派，转述不能替代语义判断。
- **当前：** 目的、背景、行动、结果和边界组成跨模型稳定的骨干；当前模型、宿主或工具不能可靠推导的说明、例子和固定协议作为血肉贴在骨干上。模型或宿主变化时先保持骨干，再复审血肉，以跨版本行为一致作为验收。
- **已吸收：** 早期把语义责任固定写成“主 agent 直接完成”、把固定清单交给 `worker`；后来改为按当前调度配置选择执行者，保留“最终责任不能转交”的机制。

### 恢复模型需要形成的判断

- **当前：** 用目的、背景、行动、结果和边界检查语义是否完整：目的说明为什么做和取舍时保护什么；背景提供现实情况与已有理解；行动说明需要做什么以及真正影响结果的方法；结果说明完成状态和证据；边界说明保持项、权限、风险护栏和停止条件。
- **当前：** 这五项是理解视角，不是固定模板。简单指令可以只有一个动作；复杂、长期或多轮校准的规则应足以让第一次阅读的模型理解目标、理由、完成条件和不可越过的边界。
- **已吸收：** 角色、语气和受众通常属于目的或背景；示例用于校准难以言明的效果或边界。当前通过“语义视角”和例子校准原则承载，不要求固定归类。

### 原则、例子与封闭规则

- **当前：** 无法穷尽的现实情境用能够生成判断的机制表达，不把见过的情况写成适用条件。
- **当前：** 抽象原则需要校准时，使用少量具有差异的例子展示共同关系怎样作用，让模型迁移到未列情境；例子不是完整分类、触发清单或适用范围。
- **当前：** 固定字段映射、准确工具协议、权限边界等封闭事实和机制直接明确规定，不能依赖类推补全。
- **当前：** 培训手册式规则和直接对话例子可以并存；规则承载目的、责任、机制和边界，例子校准难以言明的语气、关系、感觉或原则作用方式。明确规则和边界与例子冲突时以前者为准。
- **当前：** 不能因为例子不增加显式事实就删除，也不能把例子中的醒目措辞提炼成普遍规则。
- **当前：** 不能用减少项目数量、压成密集句子或改成宽泛名词冒充提取原则。
- **当前：** 开放现实不枚举见过的情境来代替原则。只有集合确实封闭，或各项会独立改变行动并需要逐项核对时才列举；列表形式本身不证明枚举必要。

### 权威层级与 Skill 分工

- **当前：** 按责任、直接证据、决策权和目标使用时的稳定信息链放置规则；文件层级或组织层级不能单独决定事实与判断的归属。
- **当前：** 写入规则前检查目标使用时共同生效的运行时指令、工具机制和按需材料。现有机制已经可靠产生所需行为时不再重复，机制没有决定使用时机时只保留触发条件。
- **当前：** 多 Agent 体系中的上下级明确谁协调、整合并作出职责范围内的决定，不改变事实的证据强度。直接接触原始资料或真实运行的角色报告相应证据但不自行夺取整体任务。负责裁决的角色必须处理证据，不能凭印象压过现实。
- **当前：** 跨角色机制分别写清各端责任；只有所有目标阅读者都会稳定获得另一来源时，当前层才删除对应规则。
- **当前：** 角色行为由角色提示词负责，项目事实和项目工作方式留在项目层，会变化的配置事实靠近当前配置来源。
- **已取代：** 仅按“最接近权威来源”选择规则位置。它忽略了直接证据、实际信息传递和跨角色接口，现由四项判断共同取代。
- **已吸收：** 正文曾显式要求同时使用 `skill-creator`。该 Skill 的 `description` 已负责创建或修改 Skill 时的触发，本 Skill 不再重复路由；其结构、资源和静态校验职责仍然有效。
- **已吸收：** 成熟 Skill 以长期稳定的目的、工作主干和完成方向为骨架；每次触发都要影响行为的规则直接保留，按需材料和确定性资源才移入参考、脚本或资产。当前由骨干、血肉和稳定信息来源共同承载。
- **历史候选：** 早期明确区分 frontmatter `description` 的触发职责和正文的执行职责，并要求触发范围或用户界面含义变化后检查 `agents/openai.yaml`。当前由平台的 Skill 触发与创建能力提供；只有该能力不再可靠覆盖时才重新附着。

### 创建、修改、精简与恢复

- **当前：** 开始前确认目标提示词、目标阅读者、目标使用时稳定获得的指令和信息来源、版本状态、本次要改变的实际效果、现有正确效果与必须保留的边界。
- **当前：** 先验证问题是否来自提示词；加载机制、外部事实或执行过程的问题修正真实来源，不向提示词追加补丁。
- **当前：** 新建提示词从真实用途和代表性例子恢复需要形成的判断，直接写最小完整的当前版本，不为不存在的历史或假想未来增加结构。
- **当前：** 修改成熟提示词先确定本次变化，再读当前文本和会影响该判断的演变记录；历史帮助理解设计和否决原因，不让旧文字和路线永久有效。
- **当前：** 当前聊天、旧任务和用户解释是修改证据，不能因为本次能看到就假定未来运行模型也会获得。
- **当前：** 用户持续经历多个任务，而模型只在被唤醒时获得当前可用上下文，因此用户对自己的目标、体验、实际代价和结果接受状态通常掌握得更连续，应作为判断长期行为缺口的强证据。用户对可核实事实和形成原因的记忆仍可能有误，能核实时根据当前记录或真实状态核实。
- **当前：** 字面覆盖不等于有效覆盖。真实行为没有形成应有判断时，检查表达是否被淹没或抵消、职责是否错位以及信息是否真正传递；只有问题确定来自非提示词来源时才不修改提示词。
- **当前：** 用户未要求调整且没有问题证据的成熟部分默认保留。
- **已吸收：** 正文曾显式要求材料散乱时使用 `workflow-state-distiller`。其 `description` 已负责相应触发，本 Skill 保留“不围绕最新一句打补丁”的语义，但不再重复路由。
- **当前：** 根据恢复出的整体判断起草连贯的当前规则，不沿原文逐句删改；主题或措辞相近不代表作用相同，删除、合并或迁移职责前确认目标模型仍会形成相同的有效判断。
- **当前：** 只有所有目标阅读者都会稳定获得另一层规则时，当前文件才不再重复它。
- **历史候选：** 范围大或版本多时，可以在动笔前临时整理语义差异；简单修改不为过程本身制造额外文档。当前没有常驻这条，按任务需要使用。

### 明确程度、证据与禁令

- **当前：** 规则明确程度随模型无法可靠推导的程度和错误代价增加：普通且易纠正的选择留给模型，难以言明的体验用少量例子校准，脆弱、危险或不可恢复的机制写到足以避免错误。
- **当前：** 适用范围和措辞强度服从证据。用户否定结果只证明结果不符合需要，不自动证明模型对原因的解释；未经证实的原因不写成确定机制或长期规则。
- **当前：** 体验校准依据真实对话、用户纠正和被接受的样本，不为抽象整齐机械改写。
- **当前：** 以正面目的、判断原则和期望行动为主；禁令只作为反复出现或高代价失败机制的窄边界，不把一次纠正扩张成普遍禁止。
- **当前：** 未指定的选择不视为禁止，也不扩大明确权限范围。
- **当前：** 不把用户没有确认的数量、顺序或偏好固化成要求；未指定选择只在既定目的与边界内留给模型。
- **已吸收：** 早期把安全、权限、数据保护和不可逆后果列为保留直接禁令的例子；当前由错误代价和窄边界原则覆盖，这些例子不构成封闭清单。

### 结构

- **当前：** 所有提示词默认按稳定主题组织；标题优先命名一个完整概念，只有内容足以独立展开或确实需要定位时才单独分节。
- **当前：** 段落表达连续关系，无序列表表达并列规则，有序列表表达真实步骤、阶段、优先级或判断顺序，嵌套列表表达从属关系。
- **当前：** 多个独立规则需要逐项展开时，不用分号压成长句；章节允许长短不一，使用能够准确表达语义关系的最浅层级。
- **已取代：** 用粗体标签代替结构，或根据一个格式示例机械复制标题深度。两者都只复制外观，没有恢复内容之间的真实关系。

### 复审与验证

- **当前：** 以第一次阅读的目标模型复审目标使用时稳定获得的完整指令链和信息来源，而不只检查修改文件；确认它能处理未列情境和目标冲突、保留既有正确效果并实现本次变化。
- **当前：** 当前修改任务的临时对话只能作为证据，不能掩盖未来稳定信息链中的缺口。
- **当前：** 不同表达会改变行为时保留差异，不为表面整齐合并。
- **当前：** 验证强度对应提示词承担的风险和证据层。文字、重复和过时事实问题可静态复审；加载、复杂行为和高代价边界需要相应验证。
- **当前：** 文本写入、宿主加载和真实行为符合预期是不同结论，只声明实际观察到的层次。
- **已吸收：** 早期还显式检查触发、优先级、局部细节是否夺走注意力；当前由完整注入上下文、目标冲突和行为差异复审覆盖。

### 生效文本、演变记录与版本控制

- **当前：** 生效文档只呈现当前指导。仍帮助运行模型判断和取舍的原因留在生效指导；只解释某次变化的历史理由留在版本记录或演变说明，不把过程、日期、哈希和命令堆进提示词。
- **当前：** 成熟功能块分别维护规则储藏库与保真并集：储藏库保存历代规则、来源和状态；保真并集只保留仍然正确、且当前或在可识别条件下仍可能适用的行为规则，排除过时、错误或失效项。两者都不写入生效文本，保真并集成员也不自动生效。
- **已取代：** 初版建议重要阶段按固定字段记录目标、原状态、问题或证据、形成的理解、实际修改、保持边界、否决路线和验证状态。当前保留这些信息的用途，但不要求固定字段或每次追加流水账。
- **当前：** 重要提示词和长期规则默认使用 Git。修改前找覆盖目标文件的现有仓库，不在已有项目中擅自建立嵌套仓库；无仓库且范围清楚时建立仅本地仓库，不配置远程或上传。
- **当前：** 已有仓库保留其他改动并确认修改前状态可恢复；修改后检查真实 diff，用说明行为变化的提交保存；不把旧备份伪造成过去的提交。
- **当前：** Git 已完整保护当前状态时不重复制造普通备份；Git 无法保护修改范围时，用只读快照和哈希补足。
- **当前：** 功能块、旧版和演变材料用于理解设计，不要求生效提示词保留对应结构；模型、宿主、关键工具、依赖或使用场景变化后，重新判断旧内容是否仍然必要。

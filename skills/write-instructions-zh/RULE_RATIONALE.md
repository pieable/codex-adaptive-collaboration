# `write-instructions-zh` 当前规则及其原因

这份文件不参与 Skill 运行。`SKILL.md` 是当前生效正文，`references/eval-cases.md` 保存维护本 Skill 时使用的评测案例，`MODIFICATION_LOG.md` 保存历史演变和旧规则。本文件只说明当前正文中的各项独立行为为什么仍需保留，供以后修改本 Skill 时核对。

修改本 Skill 前，先保存当时的 `SKILL.md`、本文件和评测案例，把它们当作检查新稿的答案。先说明本次要改变哪些规则。没有列入本次变化的规则和承载它们的原文保持不变。新稿检查完成以前不改这些答案。确认新稿没有漏掉旧规则，也没有加入未同意的新规则后，才让新稿生效并更新本文件和评测案例。

## 这份规则说明从哪里来

每项理由和历史案例优先从现有材料还原，不要求用户凭记忆重新解释。当前正文、`MODIFICATION_LOG.md` 的演变记录和规则储藏库、`references/eval-cases.md`、Git 的精确差异和提交记录、Prompt Lab 的演变文档与冻结快照，以及能够定位的旧任务记录共同构成来源。当前公开仓库没有保存某个旧提交对象时，继续使用演变记录中留下的提交号和对应冻结快照，不把无法在当前仓库执行 `git show` 误判成历史不存在。

材料直接写明的内容作为事实。需要结合多处记录才能得出的结论标明为推断。材料互相冲突或暂时无法还原理由时，现有规则继续保留并标为待确认，不由维护者补造理由，也不要求用户先读完全部历史才能获得保护。

本文件和当前正文同样需要历史核对。规则正在生效、位于最新提交或已经写有理由，都不能单独证明它正确。历史证据可能把规则确认成仍然有效、条件适用、已经迁移、已经取代、用户否决、实验失败、暂停、尚未验证或未知。相应状态必须保留，不能全部压成“当前规则”。

用户发现某一批修改已经漏掉、弱化或擅自增加规则，并要求继续排查时，维护者主动核对这一批的全部差异和相同改法波及的位置。用户不需要继续逐条找问题。

下面的“保护方式”含义如下：

- **语义：** 文字可以局部调整，但目标模型形成的判断、行动、权限和边界不能改变。
- **结构：** 规则之间的上位、下位、并列或步骤关系本身会影响理解，不能只保留零散句意。
- **精确：** 完整字段、固定协议、成熟有界清单或具体高风险边界不能压成宽泛提醒。

## WI-00 触发范围覆盖提示词体系的创建与维护

**当前规则：** frontmatter `description` 让本 Skill 在创建、修改、精简、恢复或审查提示词、Base Instructions、`AGENTS.md`、Agent、Skill 指令和长期规则时进入候选。

**为什么保留：** Codex 依靠 `SKILL.md` 的 name 和 description 进行隐式匹配。只写“修改提示词”会漏掉恢复、审查和长期规则维护；只写某次高频事故又会把原本完整的元 Skill 缩成单一修复工具。

**保护方式：** 精确。入口可以保持简短，但不能删除会改变是否触发的任务类型。

**当前承载：** `SKILL.md` frontmatter；`MODIFICATION_LOG.md` 的 description 完整范围；OpenAI 官方 [Build skills](https://learn.chatgpt.com/docs/build-skills)。

## WI-01 以真实行为和用户效果判断提示词是否成功

**当前规则：** 提示词的目标是让目标模型在真实使用中持续形成用户期望的行为，并在模型、宿主和工具变化后保持效果。

**为什么保留：** 历史上多次把字数减少、目录整齐、文字连贯或另一模型表示“能理解”当作改进，真实任务却出现行为回退。没有这条规则，维护工作容易重新围绕文本外观，而不是用户实际得到的结果。

**保护方式：** 语义。它是其余编写和验证规则的上位目标。

**当前承载：** `SKILL.md` 的“目标”“通用审查”和“验证实际效果”；评测案例的通过标准及案例八、十一、十三。

## WI-02 用目的、背景、行动、结果和边界恢复完整意思

**当前规则：** 根据实际需要从目的、背景、行动、结果和边界五个方面恢复提示词骨架；它们是理解视角，不是每次必须逐项填满的格式。

**为什么保留：** 只写动作会丢失取舍依据、完成条件和停止边界，只写原则又会让模型猜测怎样行动。五个方面让跨版本仍需保持的内容有稳定位置，同时允许简单提示词保持简单。

**保护方式：** 结构。五个方面各自承担不同信息，不能压成“写清要求”一类提醒，也不能机械改成固定表格。

**当前承载：** `SKILL.md` 的“确定提示词需要说明什么”；`MODIFICATION_LOG.md` 的当前愿景和“恢复模型需要形成的判断”。

## WI-03 区分跨版本骨架与当前环境所需的具体说明

**当前规则：** 长期目的、责任和完成逻辑构成骨架；当前模型、宿主和工具不能可靠推导的说明、例子和固定协议作为血肉附着其上。环境变化时先保护骨架，再复审血肉。

**为什么保留：** 过去的精简一方面把稳定原则压成空泛短句，另一方面又把见过的失败逐项写成长期清单。区分骨架和血肉，才能既保持长期愿景，又允许模型和宿主变化后调整具体做法。

**保护方式：** 语义与结构。不能用“更通用”作为删除当前仍必需说明的理由。

**当前承载：** `SKILL.md` 第一个主体部分；评测案例十三。

## WI-04 用结构表达规则之间的真实关系

**当前规则：** 标题表达稳定主题和从属关系；段落、无序列表、有序列表和嵌套列表分别表达连续、并列、步骤和从属关系。结构从上位目的逐层落实到具体规则。

**为什么保留：** 历史上既出现过把多项独立规则压成长句，也出现过照着示例机械制造多级标题。两种做法都会掩盖规则关系，使下位细节更容易改变上位目的。

**保护方式：** 结构。Markdown 示例用于说明不同结构的语义，不是固定模板，也不能因“减少枚举”删除结构形式本身。

**当前承载：** `SKILL.md` 的“结构”；评测案例十。

## WI-04A 标题让第一次阅读者能够定位规则

**当前规则：** 标题直接说明本节的对象、情境或责任，使第一次阅读的人只看目录也能找到需要的内容。

**为什么保留：** 成熟提示词已经很长，维护者和模型不应为了找一条规则重读全文。为追求整齐、四字标题或统一长度而缩短名称，会隐藏章节实际责任并提高误改概率。

**保护方式：** 语义。标题长短服从可定位性，不追求外观一致。

**当前承载：** `SKILL.md`“结构”；`MODIFICATION_LOG.md` 2026-08-27 结构复核；评测案例十。

## WI-04B 拆分粒度服从完整概念

**当前规则：** 一个标题优先表达一个完整概念；一句能说清的判断直接写一句，多个独立规则或真实关系再展开结构。

**为什么保留：** 机械拆分会产生大量空标题和断裂上下文，机械合并又会让独立规则藏进长句。以完整概念为单位，既保留可执行差异，也避免目录膨胀。

**保护方式：** 结构。不能用统一段落长度或固定层数替代语义判断。

**当前承载：** `SKILL.md`“结构”；`MODIFICATION_LOG.md`；评测案例十。

## WI-04C 使用足以表达真实关系的最浅层级和稳定术语

**当前规则：** 标题、列表和嵌套只表达真实从属、并列或步骤关系，使用能够准确表达这些关系的最浅层级。领域已有且含义稳定的术语可直接使用；其他概括改为普通语言，必要时首次说明。

**为什么保留：** 过深结构迫使读者跨多层才能拼回规则，生造或含义不稳定的词又要求模型自己猜“它指什么、怎样行动”。两者都会让形式和作者私有词汇遮住规则本身。

**保护方式：** 结构与语义。最浅不是永远只用一级标题，普通语言也不意味着删除准确的领域术语。

**当前承载：** `SKILL.md`“结构”“通用审查”；评测案例十、十五；Git `df35755`。

## WI-05 先限定本次真正要改变的表现

**当前规则：** 动笔前说明目标模型要在什么情况下改变什么表现，并列出本次新增、修改、迁移和删除的规则。没有列入变化的成熟原文保持不变。用户已经不信任某一批修改并要求排查时，检查这一批全部差异和相同改法波及的位置，不要求用户逐条找问题。

**为什么保留：** 大型提示词修改反复把一个局部问题扩成全文重写，随后出现旧规则遗漏和未经确认的新规则。用户无法逐份读完庞大的提示词体系，发现一项异常以后也不应继续承担寻找同批全部问题的责任。先限定变化，并在一批修改失去信任时主动扩大保真检查，才能同时保护没有问题的内容和找回同批损坏。

**保护方式：** 语义与精确。本次允许变化的项目必须明确，未列内容不能被顺带改写。一批修改失去信任后的排查属于已经明确的恢复范围，不是任意扩大重写。

**当前承载：** `SKILL.md` 的“明确本次要改变的表现”；评测案例一、十二、十八。

## WI-06 把用户的长期体验当作重要证据，同时核实可验证事实

**当前规则：** 用户对跨任务目标、体验、实际代价和结果接受状态掌握得更连续；这些说明是判断行为问题的重要线索。文件状态、运行原因和其他可验证事实仍根据当前记录核实。

**为什么保留：** 当前模型通常只看到一次任务，很容易把反复发生的问题误判为偶然情况；反过来，用户和模型对技术原因的记忆都可能不准确。两类证据必须同时保留，不能互相替代。

**保护方式：** 语义。

**当前承载：** `SKILL.md` 的“明确本次要改变的表现”；评测案例一、八。

## WI-07 先确认问题是否真的应该通过提示词修复

**当前规则：** 已有相近文字却没有形成目标行为时，检查规则表达、位置、冲突和传递；问题来自加载、配置、工具或执行过程时，修正真实来源。

**为什么保留：** 过去层级和运行机制的问题曾被误判成 Root Base 的问题，造成错误层级的大量修改。另一方面，字面上有一句相似规则也不能证明提示词实际有效。

**保护方式：** 语义。不能退化为“有相似句子就不改”，也不能把所有失败都写成新规则。

**当前承载：** `SKILL.md` 的“明确本次要改变的表现”和“确定规则放在哪里”；评测案例七、八。

## WI-08 修改成熟提示词前恢复现有规则的来路

**当前规则：** 先读当前文本、修改日志和保真并集。这些材料不能解释相关规则时，继续查 Git、旧版、备份、会话和其他相关文档。成熟而且关联较多的提示词维护不参与运行的当前规则说明，区分能够核实的事实、由材料支持的推断和仍待确认的理由。新建提示词不制造不存在的历史。

**为什么保留：** 不理解规则形成原因就精简，容易删除过去用来修复真实高代价问题的边界。把理由和来源整理成当前说明，可以让后续维护先查清楚再动手，而不需要用户反复回忆，也不需要每次无差别重读全部历史。暂时没有还原清楚的理由不能由模型自行编造，更不能成为删除规则的理由。

**保护方式：** 结构。读取顺序表达由当前到历史、按缺口扩大的关系，不是要求每次穷尽所有档案。

**当前承载：** `SKILL.md` 的“恢复现有提示词的来路”；评测案例六、十一、十二、十七、十八。

## WI-09 只把未来运行模型稳定需要的内容写进生效提示词

**当前规则：** 当前会话和旧任务用于发现规则及其原因；只有未来目标模型仍需获得的当前指导进入稳定加载位置，临时证据和修改过程留在维护材料中。

**为什么保留：** 当前修改会话包含大量用户解释和历史背景，运行模型以后通常看不到。若依赖这些临时材料，提示词表面完整，实际调用仍会出现信息缺口；若把全部历史塞进正文，又会污染注意力。

**保护方式：** 语义。

**当前承载：** `SKILL.md` 的“恢复现有提示词的来路”和“保存修改记录”；评测案例六、七。

## WI-10 按实际阅读者、责任和加载关系放置规则

**当前规则：** 共同方法、角色行为、项目事实和易变化配置分别放入对应层；检查目标 agent 实际收到的完整调用，只有新来源会被所有目标阅读者稳定获得时才删除旧位置。

**为什么保留：** 提示词体系分散在 Base、全局规则、项目规则、角色、Skill 和工具说明中。过去多次出现规则迁移后目标角色未必读取、Root 规则进入下级上下文、角色规则反向污染 Root 等问题。

**保护方式：** 结构与语义。文件相邻、组织层级更高或文字重复都不能单独决定归属。

**当前承载：** `SKILL.md` 的“确定规则放在哪里”和“通用审查”；评测案例二、四、七。

## WI-11 机制只有真正等价时才能替代提示词

**当前规则：** 工具、角色和工作流已经可靠产生同一行为时，可以删除重复过程说明；机制只提供执行能力而没有决定何时使用时，仍保留模型需要判断的触发条件。

**为什么保留：** 过去既有把文字换个文件就声称完成压缩，也有把工具存在误当成模型会正确选择工具。机制压缩必须减少模型实际需要承担的判断，而不是隐藏规则。

**保护方式：** 语义。没有稳定等价机制时，原判断保持。

**当前承载：** `SKILL.md` 的“确定规则放在哪里”；`MODIFICATION_LOG.md` 的“机制压缩”。

## WI-12 成熟提示词默认局部修改并保留无问题原文

**当前规则：** 只改本次变化涉及的规则，没有列入变化的成熟原文保持不变。精简、统一表达和重排结构不提供额外改写许可。只有当前结构确实无法承载已经确认的变化时，才在独立候选中重组，逐项确认原有规则去向后再替换当前版本。

**为什么保留：** 生成式全文重写会重新概括每一段，多轮重写会累积细小偏差。本体系已经多次发生一次局部要求带动数十到数百行重写，随后连续恢复被删规则。保持无关原文比事后依靠模型概括证明保真更可靠。

**保护方式：** 语义与精确。没有被列入变化范围的成熟部分默认冻结；“精简”“统一风格”“结构更清楚”本身不构成重写许可。

**当前承载：** `SKILL.md` 的“写成当前指导”和“通用审查”；评测案例十一、十二、十七。

## WI-13 区分开放现实、独立行动项和封闭规则

**当前规则：** 开放情境提炼能够迁移的判断；每项独立改变行动、完整性决定正确性、具体高风险边界不能含糊，或成熟清单有意覆盖全部有效选择时，保留完整枚举。

**为什么保留：** GPT-5.6 既容易把开放例子越列越长，也容易为了反枚举把固定合同、Ponytail 一类成熟路线集合和高风险禁令压成空泛提醒。两种错误都会改变行为。

**保护方式：** 语义与精确。不能用项目数量多少判断是否应该保留枚举。

**当前承载：** `SKILL.md` 的“写成当前指导”和 GPT-5.6 专项审查；评测案例十四、十五、十六。

## WI-14 正向说明为主，规则明确程度与风险相称

**当前规则：** 优先说明希望模型怎样判断和行动；正向机制仍覆盖不到明确边界，或同一问题反复发生时，再增加范围窄的禁令。普通可纠正选择留有自由，高代价和不可恢复问题写得具体。

**为什么保留：** 事故补丁容易不断增加禁令并限制正常工作；过度相信模型又会删掉权限和安全边界。用风险和失败证据调节明确程度，可以同时避免两端。

**保护方式：** 语义。不能机械删除否定句，也不能因为一项规则重要就自动扩成长清单。

**当前承载：** `SKILL.md` 的“写成当前指导”和 GPT-5.6 专项审查；评测案例三。

## WI-15 难以抽象说明的体验可以用少量真实例子校准

**当前规则：** 语气、关系和感觉无法仅靠原则准确传达时，保留少量会实际改变体验的例子；明确规则和边界决定适用范围。

**为什么保留：** 过去曾因例子不增加显式事实而将其删除，也曾从醒目的例句提炼出不适用于其他场景的口号。例子和规则承担不同职责，不能互相替代。

**保护方式：** 语义。

**当前承载：** `SKILL.md` 的“写成当前指导”；评测案例九。

## WI-16 通用审查必须同时检查遗漏、擅自新增和错误迁移

**当前规则：** 先逐项检查每个原有行为在候选中的准确去向，再反向检查候选中的每项新增、删除和重写是否来自已经确认的变化。没有列入变化的原文保持不变。用户要求排查一批已经失去信任的修改时，对这一批全部差异作同样检查。首次阅读的目标模型还要能够获得必要说明，迁移到的新位置会被实际读取。

**为什么保留：** 过去的内部审查常能证明文件已写、格式有效和镜像同步，却不能发现旧行为被删弱、未经用户确认的新结构混入，或者规则被迁到实际加载不到的位置。只检查旧规则有没有留下会漏掉擅自新增，只检查新稿是否连贯又会漏掉旧规则，因此两个方向都必须核对。

**保护方式：** 结构与语义。每项旧行为都要有准确去向，每项新行为都要有已经确认的来源，两个方向不能互相替代。

**当前承载：** `SKILL.md` 的“通用审查”；评测案例四、七、十一、十二、十七、十八。

## WI-19 生效正文、规则原因和历史版本分开保存

**当前规则：** 生效正文只放当前运行所需的指导。仍帮助模型判断的短原因留在正文，只解释形成过程的长原因、旧规则、失败路线和状态进入维护记录。保真并集只保存仍有效的行为。检查新稿期间，修改前的生效正文、当前规则说明和评测案例保持为对照答案；新稿通过后才一起更新为确认后的当前状态。

**当前规则：** 重要提示词沿用覆盖目标文件的现有 Git 仓库；修改前确认状态可恢复并保留无关改动，修改后检查真实 diff，用说明行为变化的提交保存。Git 无法覆盖时才补充只读备份。

**为什么保留：** 沿用覆盖目标文件的现有仓库可以避免嵌套历史和多个真相来源；修改前确认可恢复并保留无关改动，避免为了修提示词损坏用户其他工作；修改后查看真实 diff，才能知道实际新增、删除和重写了什么；提交记录保存一次行为变化的精确版本。Git 已经完整覆盖时不再制造散乱备份，只有 Git 保护不到的内容才用只读快照补足。Git 仍不能代替语义保真检查。

**保护方式：** 精确与语义。不能建立嵌套仓库、伪造历史或用提交成功冒充行为验证。

**当前承载：** `SKILL.md` 的“保存修改记录”；`MODIFICATION_LOG.md` 的 Git 与快照规则；评测案例十一、十二、十七、十八。

# 全局 `AGENTS.md` 规则理由

本文件不参与运行。核对对象是 [`../../global/AGENTS.md`](../../global/AGENTS.md)。全局层只承载所有 agent 都需要的共同工作方法，不承载 Root 的用户理解、整体路线、模型成本、Plan mode、Skill 选择或具体角色路由。

## G-01 合同内持续完成，合同外逐级上交

- **状态：** `current-effective`
- **行为：** 每项责任以合同结果和边界为准；普通、可逆细节由责任人处理；新事实会改变结果、权限或验收时沿责任链上交。
- **理由：** 同时防止执行者遇到普通细节就停下，也防止它在证据变化后擅自扩大任务。
- **案例：** C-08、C-11。
- **来源：** 当前文件“共同执行规则”；`subagent-architecture/rule-rationale.md` R1、R9、R10、R29。
- **验证：** 静态存在；各角色真实服从度仍需任务验证。
- **改变条件：** 只能在新的运行机制稳定等价承载时迁移，不能删成模糊的“按合同工作”。

## G-01A 权威需求变化时只停止和修正受影响的工作

- **状态：** `current-effective + unverified`
- **行为：** 合同引用的当前需求、规格和项目资料共同限定责任。来源变化或冲突会改变当前结果时，执行者停止受影响的行动并交回差异；未受影响工作继续。执行者不沿过时要求继续，也不改写上游来源迁就现状。
- **理由：** 复杂任务的规格更新如果没有传播规则，下游会继续执行旧计划；反过来让所有工作一律停止又会浪费已经独立且仍然有效的责任。影响范围决定停止与更新范围。
- **案例：** C-30。
- **来源：** 当前文件“共同执行规则”；Root Base“维护复杂任务的当前规格”；`subagent-architecture/rule-rationale.md` R39。
- **验证：** 静态规则已写入；真实并行阶段中的变化传播尚未验证。
- **改变条件：** 宿主将来提供可靠的版本依赖和自动失效机制时可以迁移执行细节，但不能删除旧要求不得继续、上游不得由执行者擅改和未受影响工作可继续三项结果。

## G-02 责任链和内部通信只沿当前 agent 树

- **状态：** `current-effective`
- **行为：** subagent 只向直接上级交回；有下属的负责人先整合。补充和返工交原负责人，新责任建新 agent；只在依赖仍运行结果时等待；完整报告只在完成时交一次。
- **理由：** 绕过上级、过早发消息和重复报告会唤醒高价模型、丢失整合责任，并让 Root 接管阶段细节。
- **案例：** C-11、C-21；搜索 v2 自由派生和父负责人提前结束。
- **来源：** 当前文件“责任链与内部通信”；`subagent-architecture/rule-rationale.md` R11、R12、R15、R22。
- **验证：** 历史失败已观察；当前全局版本的长期闭环待验证。
- **改变条件：** 宿主通信 API 名称可以变化，但直接上级、一次完整交回和责任所有权不能被接口变化删掉。

## G-03 内部协作不使用用户可见的 Codex 任务工具

- **状态：** `current-effective`
- **行为：** 团队内部只用 collaboration；只有用户明确要求创建、管理或联系独立任务时才使用 Codex 任务工具。
- **理由：** 内部 subagent 不应污染侧边栏或制造用户拥有的新任务，也不能用手写委派标记绕过运行时责任链。
- **来源：** 当前文件第 13 行；运行时任务工具与 collaboration 的产品边界。
- **验证：** 规则文字明确；真实 UI 副作用按宿主验证。
- **改变条件：** 只有产品明确统一两类对象且不再产生用户可见副作用时重审。

## G-04 事实、推断和未知分开

- **状态：** `current-effective`
- **行为：** 以可核实文件、配置和真实运行结果判断状态；直接接触材料的角色对观察事实负责，推断和未验证项分开报告。
- **理由：** 静态写入、工具成功或历史记忆经常被误当作宿主加载、真实行为或完整覆盖。
- **案例：** C-04、C-13、C-14。
- **来源：** 当前文件第 15 行和“验证责任”；`evolution-map.md` 的证据分层。
- **验证：** 规则存在；具体声明仍需逐任务检查证据层。
- **改变条件：** 不允许因报告变短而合并三种状态。

## G-05 复用可靠能力并选择最低复杂度

- **状态：** `current-effective`
- **行为：** 优先使用项目、平台和工具已经可靠工作的能力，以完成合同结果所需的最低复杂度推进。
- **理由：** 防止为局部任务重复造轮子和引入额外维护面，同时保留结果、风险和适配判断。
- **案例：** C-07、C-22。
- **来源：** 当前文件第 17 行；Root Base；`code-development/MODIFICATION_LOG.md`。
- **验证：** 原则有历史依据；实际选择需按项目证据判断。
- **改变条件：** 已有能力不可靠或不满足结果时可采用新实现，不能把“复用”变成强制顺序。

## G-06 每项动作必须推进结果或产生新证据

- **状态：** `current-effective`
- **行为：** 继续、重试、等待或扩大前检查动作是否推进可验收结果，或产生改变下一步的新信息；相同条件无变化不继续。外部状态变化、预定观测和比较备选是明确例外。
- **理由：** 用通用判断阻止钻牛角尖，不为每种失败另堆禁令；检查在内部完成，不生成表演式自述。
- **案例：** C-05、C-11、C-16。
- **来源：** 当前文件第 19–21 行；Root Base；`evolution-map.md` 的动作门修复。
- **验证：** 历史反例明确；真实长任务时机仍待观察。
- **改变条件：** 新的停止机制必须覆盖重试、等待和扩大三类行为，并保留监控/探索例外。

## G-07 直接入口优先，并行只用于真正独立工作

- **状态：** `current-effective`
- **行为：** 能通过接口、CLI 或文件直接取结果时优先；无依赖工作并行，依赖前一步、修改同一状态或并行无收益时顺序执行；停止运行项前处理其变化。
- **理由：** 减少不必要的 UI 步骤、模型轮次和等待，同时避免共享写入冲突和伪并行。
- **案例：** C-11、C-12。
- **来源：** 当前文件第 23–25 行；`subagent-architecture/rule-rationale.md` R3、R4、R8、R18。
- **验证：** 历史有时间/成本对照；不同工具阶段仍需现场判断。
- **改变条件：** 用户明确要求真实 UI，或完成条件本身是页面行为时，接口/CLI 不能替代真实路径。

## G-08 成品从实际使用者角度独立可用

- **状态：** `current-effective`
- **行为：** 结构、内容和交互服务真实使用任务；要求落实到成品，不用合规说明替代实现；成品不用内部术语和修改日志自述。
- **理由：** 局部文件、实现说明或“已经处理”的报告不能替代用户能直接使用和理解的结果。
- **案例：** C-06、C-14。
- **来源：** 当前文件“把要求变成可用的成品”；`prompt-architecture/test-results.md` 的保真恢复。
- **验证：** 静态规则完整；每个成品仍需领域适配和用户路径验收。
- **改变条件：** 当用户要求的成品本身就是审计、修改日志或技术说明时可以包含过程信息。

## G-09 完成声明必须匹配证据层

- **状态：** `current-effective`
- **行为：** 完成前先视为未证实，逐项确定证据；文件写入、解析、构建或局部测试不能单独证明宿主加载、逻辑符合用户需要或实际交互可用；关键证据缺失时明确停点。
- **理由：** 大量失败来自把低层成功升级成产品、宿主或真实模型完成。
- **案例：** C-02、C-04、C-13、C-14。
- **来源：** 当前文件“验证责任”；`evolution-map.md` 的 static/mirror/fresh-task/real-behavior 分层。
- **验证：** 规则文字已稳定；具体任务的证据覆盖必须逐项核对。
- **改变条件：** 新自动化只能替代它真实覆盖的证据层，不能因测试全绿删除真实入口要求。

## G-10 Windows PowerShell 和文件安全

- **状态：** `current-effective + conditional`
- **行为：** 默认 PowerShell 7；复杂逻辑使用临时脚本，禁止 `Invoke-Expression`，检查外部错误码和编码；难恢复文件操作先在同一 PowerShell 进程核实绝对目标，保留未知改动，避免破坏性 Git 命令。
- **理由：** 引号、编码、跨 shell 路径传递和宽范围删除可能造成数据损失；这些高风险边界不能压成一般性“安全操作”。
- **案例：** C-03；2026-08-14 高风险规则压缩后由用户要求恢复。
- **来源：** 当前文件“在 Windows 中执行任务”；`prompt-architecture/test-results.md` 高风险块和加载探针。
- **验证：** 加载探针支持部分角色已收到；真实操作仍需每次核实对象和授权。
- **改变条件：** 仅在平台或 shell 改变时调整具体命令；防止路径误判、命令注入、编码破坏和覆盖用户内容的机制继续保留。

这一组是高风险的有界保护，不能只保留上面的概括。当前具体规则及其作用如下：

| 当前保护 | 为什么单独保留 |
|---|---|
| 默认 PowerShell 7；需要新进程时用 `pwsh -NoProfile -NonInteractive` | 统一编码和非交互行为，避免用户 Profile 或交互提示让任务结果不可复现 |
| 仅在受信任脚本确被执行策略阻止时用 `-ExecutionPolicy Bypass` | Bypass 会放宽当前进程的脚本限制，不能作为普通启动参数 |
| 复杂管道、变量、JSON、正则和大量引号写入临时脚本后运行并清理 | 多层 Shell 引号曾造成转义和命令边界错误；临时脚本让实际执行内容可检查 |
| 禁止 `Invoke-Expression` 和字符串拼命令；程序路径与参数分开 | 防止文本意外变成命令、变量展开或命令替换，也避免空格路径改变参数边界 |
| 设置 `$ErrorActionPreference = 'Stop'` 并检查 `$LASTEXITCODE` | PowerShell 成功状态不能自动代表外部程序成功，遗漏检查会继续使用失败结果 |
| 机器读取对象时选明确字段或足够深度 JSON | PowerShell 默认表格会截断字段，截断显示不能作为完整机器数据 |
| 任务变量不复用 `$HOME`、`$home`、`$CODEX_HOME` | PowerShell 变量名大小写不敏感，覆盖系统变量会改变后续路径和运行环境 |
| PowerShell 7 默认 UTF-8；Windows PowerShell 5.1 中文脚本使用带 BOM 的 UTF-8 | 两代 PowerShell 的默认编码不同，无 BOM 中文脚本在 5.1 中可能被错误解码 |
| 沙箱中 `gh` 凭据读取失败先提升做只读认证检查 | 管理员 keyring 在沙箱内不可读不等于凭据失效，避免无意义重新登录或把令牌落成明文 |
| 路径操作使用 `-LiteralPath` 和 `Join-Path` | 防止通配符、方括号和字符串拼接让实际对象偏离用户指定路径 |
| 难恢复操作在同一 PowerShell 进程解析并核实绝对目标，不跨 Shell 传递删除或移动列表 | 路径在另一 Shell 中可能被重新解析；核验和操作分离会让安全检查失效 |
| 不把根目录、主目录、工作区根或宽范围目录作为递归目标 | 这类对象一旦选错会造成远超任务范围的数据损失，必须明确阻止 |
| 来源不明的改动视为用户内容，保留无关部分；不默认使用破坏性 Git 恢复 | 现有脏改动和新文件可能是用户尚未提交的工作，不能用清理工作区覆盖 |

具体故障来路由私人 `codex-base-history.md` 的“PowerShell、Windows 与文件编辑”、高风险压缩恢复记录和当前全局文件共同保存。若以后调整某一项，需要针对这一行核对平台行为，不能以“G-10 的大意还在”为理由删掉。

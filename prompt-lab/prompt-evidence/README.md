# 提示词规则证据库

本目录不参与运行时加载。它用于逐份保存龙珠 Agent 提示词中每项规则的理由、历史案例、来源、状态、承载位置和允许改变的条件，避免以后只能靠用户重新回忆，或者由修改者用自己的概括证明新稿没有漏规则。

当前正在生效、位于最新提交、写进保真并集或已经有理由说明，都不能单独证明一条规则正确。每次核对都从当前文本、Git 精确差异、冻结快照、演变文档、旧任务结果和用户后续决定共同恢复状态。

## 状态

| 状态 | 含义 |
| --- | --- |
| `current-effective` | 现有证据支持继续生效 |
| `conditional` | 只在明确条件下适用 |
| `migrated` | 行为仍需保留，但当前由其他位置承载 |
| `superseded` | 已被后续规则或可靠机制取代 |
| `user-rejected` | 用户明确否决，不得自动恢复 |
| `experiment-failed` | 实验或真实任务已经证明该路线失败 |
| `paused` | 暂停推进，等待条件、授权或新证据 |
| `unverified` | 已形成文字或静态证据，关键运行层仍未验证 |
| `unknown` | 现有材料还不能可靠判断 |

一条规则可以同时带有适用状态和验证状态，例如 `current-effective + unverified`。`unknown` 不等于错误，也不授权删除。

## 每份理由文件记录什么

每个独立行为至少记录：

1. 当前或历史规则实际要求模型形成什么判断和行动。
2. 这条规则为什么出现，删掉或弱化后会重新发生什么问题。
3. 对应的真实失败、用户纠正、否决路线、前向测试或其他历史案例。
4. Git 提交、冻结快照、文档章节或旧任务等精确来源。
5. 当前状态、实际承载位置和验证到哪一层。
6. 什么条件出现后才允许修改、迁移或删除。

材料直接写明的内容按事实记录。需要结合多处材料才能得出的结论标明为推断。找不到理由或材料冲突时保留原文并标为 `unknown`，继续追查，不补造原因。

## 工作顺序

1. 先固定修改前的正文、理由文件、案例索引和版本清单。
2. 从历史恢复规则，不把当前文本当作答案。
3. 对照旧规则检查新稿的去向，再反向检查新稿中的每项新增、删除和重写是否有已经确认的来源。
4. 用户已经不信任一批修改时，检查该批全部差异和同类改法波及的位置，不要求用户继续逐条找问题。
5. 候选通过原来的检查材料后，才更新生效正文和本证据库。

## 当前范围

- Root Base。
- 全局 `AGENTS.md`。
- Shared Runtime Base、Worker Base 和每个 Agent TOML 的 `developer_instructions`。
- 本仓库维护的每个 Skill。
- 本机存在但尚未进入公开仓库的用户维护 Skill。
- 外部、官方或来源未知的 Skill 只记录来源、版本和漂移，不把上游规则伪装成本机用户规则。

本机额外 Skill 的逐项状态见 [`installed-skills.md`](installed-skills.md)。
当前 Skill 正文与理由的覆盖关系见 [`skill-coverage.md`](skill-coverage.md)，跨层重复、迁移和剩余验证项见 [`cross-layer-audit.md`](cross-layer-audit.md)。

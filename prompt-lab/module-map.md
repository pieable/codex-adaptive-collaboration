# 当前 Base 的功能块地图

## 两类规则与三种材料

当前 Base 同时承担两类工作，不能用同一种精简方法处理：

- **交互校准：** 人格、语气、写作风格、技术交流、面向用户的进度和交付体验。它们来自长期纠正和主观感受，默认保留成熟运行版；修改时使用真实对话、代表性样例和成对场景校准。
- **操作手册：** 工具、文件、PowerShell、权限、自主推进、测试、多代理、安全和 Skill。普通工作只写直接行动和判断标准；易错、不可逆或涉及权限的操作降低自由度，写清固定顺序与停止条件。

三种材料各有用途：

- `codex_base_instruction_5.6.md` 是当前运行版，也是现行规则的权威文本。
- `functional-block-baseline.md` 是模型或宿主变化后的实验起点，不直接替换运行版；每个功能面只保留能够独立工作的最小块。
- 修改记录、只读备份和 Git 分别保存形成理由、恢复规则库和精确版本，不进入日常运行上下文。

## 多代理功能块当前装配

Root 负责整体路径、关键判断、报告整合和最终结果；低成本角色承担能够可靠交接的完整阶段。模型成本、输入输出价格和上下文流向只提供判断背景，不构成机械评分。

- 无需工具或一次输出有界的工具批次由 Root 直接完成。
- 多轮工具调用或单次大量输入阶段交给合适 subagent。
- 合同写清责任、必要来源、交付与验收、保持项、权限和停止边界。
- 每项责任只由一个 agent 负责；交出完整阶段后 Root 停止该阶段，没有其他工作时使用 `wait_agent`。
- 相关后续使用 `followup_task`；无关上下文使用新代理。
- 完整报告默认采信，只有具体矛盾、重要缺口或较高错误代价才定向核验。
- 浏览器交互阶段交给一个 `browser-operator` 连续完成。

## 修改条件

真实任务反复出现同一种普通操作错误时，从修改前完整版和演变记录恢复对应规则需要的最小完整细节。高风险功能块不等待事故样本：只要省略的步骤可能造成越权、数据丢失或凭据风险，就保留明确流程。交互校准只有在真实对话或持续用户反馈显示同一问题时修改，不从单次静态判断重写整个分区。

模型、宿主或关键工具变化时，可以从功能块基线重新测试操作规则。交互规则先保留成熟版本，再观察新模型的真实交流表现。

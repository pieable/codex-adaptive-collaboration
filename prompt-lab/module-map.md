# 当前 Base 的功能块地图

## 方法

模型升级或重新设计提示词时，起点是 `functional-block-baseline.md`：保留完整功能面，但把每块写成能够独立工作的最小版本。每块通常包含一句目标或必要背景，再写少量直接行动；只有确实需要时才加入禁止项、例子或短流程。

测试发现某个功能块出现稳定退化时，从当前完整版和演变记录中恢复该块需要的细节。其他已经通过的功能块保持不变。

## 多代理功能块当前装配

### 目标与背景

Root 负责整体路径、关键判断和最终结果；低成本角色承担可可靠交接的完整阶段。模型成本、输入输出价格和上下文流向用于自主选择执行结构。

### 直接行动

- 小型、有界工具批次由 Root 直接完成。
- 多轮工具调用或单次大量输入阶段交给合适 subagent。
- 完整阶段只有一个所有者；交出后 Root 停止该阶段并使用 `wait_agent`。
- 报告返回后安排后续，没有新工作时再次等待。
- 相关后续使用 `followup_task`，无关上下文使用新代理。
- 完整报告默认采信，具体矛盾或高风险缺口才定向核验。
- 浏览器交互阶段交给一个 `browser-operator` 连续完成。

### 当前未装配的详细说明

- 独立阶段并行、强依赖和共享修改范围的详细判断。
- `fork_turns` 合同构成与无关上下文的完整解释。
- followup 复用中“应用既定做法”和“重新判断方案”的细分。
- 线程额度用途与浏览器逐步接管的更多反例。

这些说明保存在修改前完整版和演变记录中；对应测试出现稳定退化时按完整功能块恢复。

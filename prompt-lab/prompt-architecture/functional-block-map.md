# Root Base 功能块地图

## 结构与层级

可维护的提示词正文从大到小组织：目的与原则先说明要解决什么；责任与权限界定谁能决定和行动；路线与阶段说明何时推进、交接或换路；具体行动与工具描述执行方法；验证、交回与例外限定完成声明和停止条件。功能块应保持在最适合的真实加载层，不因文档相邻而复制。

## 规则性质

当前 Root Base 同时包含两类内容，维护时不能用同一种精简方式处理：

- **交互校准：** 人格、语气、写作风格、面向用户的进度与交付体验。它们来自长期纠正和主观感受，修改时使用真实对话、代表性样例和成对场景校准。
- **工作方法：** 用户理解、授权、路线、验证、调度和 Skill 选择。它们按目的、条件、行动和证据关系组织，并通过真实任务或相称的静态检查核验。

## 当前功能块与承载层

| 功能块 | 主要承载层 | 维护边界 |
| --- | --- | --- |
| 主 agent 的目的、用户理解、授权、整体路线、任务阶段与最终交付 | Root Base | 只有 Root 必须持续判断的跨任务规则留在这里 |
| 所有责任层共同的执行、成品、验证、文件与环境规则 | 全局 `AGENTS.md` | 不复制回 Root Base |
| 阶段负责人、执行者及命名角色的职责和工具边界 | `agents/*.toml` 与 Worker Base | 阶段角色分别维护完整专属提示词；八个执行角色共享 Worker Base |
| 代码开发、研究、批处理等领域方法 | 对应 Skill | 按任务触发加载 |
| 平台参数、工具协议和实际加载行为 | 当前配置与工具说明 | 不用静态提示词替代运行时事实 |

`../functional-block-baseline.md` 是当前功能块的保真基线和快速比较入口，只覆盖局部功能面，不替换运行版，也不构成完整发布验收。`../evolution-map.md` 记录公开版本的行为演变、迁移和否决状态。公开发行仓库不携带个人会话、本机备份、账户配置或完整内部历史；这些材料也不进入日常运行上下文。

## 多代理功能块

Root 负责用户意图、整体路线、跨阶段判断、报告整合和最终验收。结果、做法和验收已经固定且责任彼此独立时，可以直接交给执行角色；需要持续形成方案、组织下属、协调共享状态或反复整合时，交给阶段负责人。每项结果只有一个负责人，阶段负责人完成内部等待、返工、冲突处理、整合和验收后再交回 Root。

阶段合同未授权的高成本运行、大范围结构修改或明显增加下属轮次，阶段负责人先报告当前代表性结果、首个缺口、拟新增证据、成本和替代路线。完整报告有合同和自洽证据支持时直接采用，只在具体矛盾、关键证据缺口或较高错误代价下定向核验。

## 修改条件

修改前先确认问题是否跨任务发生，以及 Root 是否必须知道该规则才能行动。工具、角色、全局共同规则或 Skill 已稳定提供的行为不再写回 Root Base。模型、宿主或关键工具变化时，先从唯一功能块基线检查对应功能面；实验结论记录在 `test-results.md`，当前架构以本文件和运行时加载说明为准。

# Agent 提示词演变、规则储藏库与保真并集

本文件不参与运行。Git 历史是完整规则储藏库，可以保存已经取代、过时、错误或失效的原文；提交 `67896c5` 保存了自包含重写前的七份提示词和配置。下面的保真并集只记录经核对仍然正确、当前或在可识别条件下仍可能适用的行为规则，不表示这些规则必须以原句出现在每份提示词中。

## 保真并集

所有角色都围绕一项能够明确交接和验收的责任工作，在职责内连续处理普通变化，遇到原合同已经不足以决定结果或授权的问题才交回上级。角色提示词只保留该角色需要形成的判断；FastCtx 由全局 `AGENTS.md` 提供，需要动态权限和环境的角色由各自配置请求宿主注入。

直接执行角色隔离原始材料、中间输出、工具调用和执行过程，返回完成物、必要原始证据、验证、限制和未验证项，不解释用户意图、不选择整体路线、不替上级作最终结论。阶段负责人可以在合同内组织子任务并形成阶段判断；代码评审者可以在评审合同内作独立判断，这些局部判断都不扩大为用户或整体任务决策。

`explorer` 保持只读，以会改变回答的证据缺口决定读取范围。`web-researcher` 以主张和来源距离决定搜索路线。`browser-operator` 依据动作的真实外部后果判断授权，并以可见页面验证流程。`worker` 和 `worker-luna` 只执行结果含义和边界已经确定的责任，但可以自主完成合同内普通细节和修正。`visual-usability-tester` 只通过可见截图和坐标交互，从首次使用者视角检验合同指定的成品路径。

`research-lead` 使用 Terra 连续负责完整研究阶段。它先定位研究对象、范围和当前状态；只看当前现象不足时，沿时间关系追溯形成原因并明确目标，答案依赖方案或对象比较时，选择相近条件下的参照和可比维度，再把这些关系转成主张、候选、来源系统、竞争解释和未知的覆盖结构。能够独立取证并扩大覆盖的路线及时并行交给 Luna 搜索角色；代理数量不预设为“少量”，报告到达后持续整合并补查新暴露的缺口，直到新增独立路线已不太可能改变结论、候选范围或关键不确定性。`code-executor` 以上级给出的成功条件、边界和验收要求为语义边界，只恢复合同内实现所需的系统事实并自主选择内部实现；把可可靠交接且值得隔离的部分交给价格更低的角色。代码阶段按依赖和共享状态组织执行，优先启动会解锁后续或产生长等待的工作，只并行能够独立验收且写入范围不重叠的责任，不与已经交出的子阶段同时修改同一状态；报告到达后推进已解锁的后续，并安全停止已经不会影响合同结果的运行项。当前 `explorer`、`web-researcher`、`worker-luna`、`browser-operator` 和 `visual-usability-tester` 使用 Luna，模型价格约为主 agent Sol 的 1/25；`research-lead`、`code-executor` 和 `code-reviewer` 使用 Terra，约为 2/5；`worker` 的独立额度 Spark 按接近 Luna 的价格考虑。代码阶段以误交付风险决定验证和独立评审，不把测试或评审变成无条件流程。`code-reviewer` 保持只读，只报告本次变更产生或暴露的可操作问题。

开放现实使用能够生成判断的原则表达；少量例子只用于校准，不构成分类、触发清单或适用范围。运行时工具语义、权限边界和其他封闭协议保持必要精度。

## 2026-08-27 使用注册说明和共同执行层

角色的使用时机由各自 TOML 中的 `description` 提供。注册配置只引用角色文件，不再维护第二份容易漂移的描述。视觉测试的说明现在直接告诉上级何时使用该角色，Spark Worker 的说明直接提供独立额度和速度条件。

所有角色共同需要的 collaboration 工具选择、成品和验证规则由全局 `AGENTS.md` 承载。阶段负责人提示词只保留该阶段内部仍需判断的责任，不重复接口、CLI、等待和轮询过程。

## 2026-08-16 自包含重写

停止使用共享 XML 区块。原因不是避免文字重复本身，而是共享内容长期混入无关职责，并使权威源与实际角色文件发生漂移。七份生效提示词改为各自完整表达角色目的、行动、结果和边界；公共历史由本地 Git 保存，不再通过运行时共享段落维持一致。

# Agent 提示词保真并集与阶段历史

本文件不参与运行，只保存 Agent 层的保真并集和重要阶段历史。整套体系按行为组织的演变、迁移、否决和验证状态见 [`../prompt-lab/evolution-map.md`](../prompt-lab/evolution-map.md)。Git 历史保存已经取代、过时、错误或失效的精确原文；提交 `67896c5` 保存了自包含重写前的七份提示词和配置。下面的保真并集只记录经核对仍然正确、当前或在可识别条件下仍可能适用的行为规则，不表示这些规则必须以原句出现在每份提示词中。

## 保真并集

所有角色都围绕一项能够明确交接和验收的责任工作，在职责内连续处理普通变化，遇到原合同已经不足以决定结果或授权的问题才交回上级。角色提示词只保留该角色需要形成的判断；共同执行规则和 FastCtx 由全局 `AGENTS.md` 提供。角色 TOML 不能请求宿主注入环境或权限；环境与权限由运行时和全局规则提供，TOML 只配置运行时实际支持的角色字段与少数禁用项。

直接执行角色隔离原始材料、中间输出、工具调用和执行过程，返回完成物、必要原始证据、验证、限制和未验证项，不解释用户意图、不选择整体路线、不替上级作最终结论。阶段负责人可以在合同内组织子任务并形成阶段判断；代码评审者可以在评审合同内作独立判断，这些局部判断都不扩大为用户或整体任务决策。

`explorer` 保持只读，以会改变回答的证据缺口决定读取范围。`web-researcher` 以主张和来源距离决定搜索路线。`browser-operator` 依据动作的真实外部后果判断授权，并以可见页面验证流程。`worker` 只执行结果含义和边界已经确定的责任，但可以自主完成合同内普通细节和修正。

`worker` 的 122K 容量限制由分配责任的 `code-executor` 使用，不写进 `worker` 或 `worker-luna` 自身提示词。`worker-luna` 与 `worker` 承担相同职责，在 Spark 额度耗尽或服务不可用时备用。`visual-usability-tester` 保持截图与坐标隔离，根据合同完整测试一个功能路径，或用多项代表性用户任务检查整个软件。实现负责人使用其报告安排修正和复测，不重复已经完成的视觉检查。

`research-lead` 使用 Terra 连续负责完整研究阶段。它先定位研究对象、范围和当前状态；只看当前现象不足时，沿时间关系追溯形成原因并明确目标，答案依赖方案或对象比较时，选择相近条件下的参照和可比维度，再把这些关系转成主张、候选、来源系统、竞争解释和未知的覆盖结构。网络来源的发现、收集和路线内核验交给 Luna `web-researcher`，本地原始材料取证交给 `explorer`；`research-lead` 负责分派、持续整合、冲突处理和阶段判断，只在报告已经定位具体原文而一个明确解释差异仍会改变判断时读取最小片段。代理数量不预设为“少量”，报告到达后持续整合并补查新暴露的缺口，直到新增独立路线已不太可能改变结论、候选范围或关键不确定性。`code-executor` 以上级给出的成功条件、边界和验收要求为语义边界，只恢复合同内实现所需的系统事实并自主选择内部实现；把可可靠交接且值得隔离的部分交给价格更低的角色。代码阶段按依赖和共享状态组织执行，优先启动会解锁后续或产生长等待的工作，只并行能够独立验收且写入范围不重叠的责任，不与已经交出的子阶段同时修改同一状态；报告到达后推进已解锁的后续，并安全停止已经不会影响合同结果的运行项。当前 `explorer`、`web-researcher` 和 `browser-operator` 使用 Luna，模型价格约为主 agent Sol 的 1/25；`research-lead`、`code-executor` 和 `code-reviewer` 使用 Terra，约为 2/5；`worker` 的独立额度 Spark 按接近 Luna 的价格考虑。代码阶段以误交付风险决定验证和独立评审，不把测试或评审变成无条件流程。`code-reviewer` 保持只读，在完整评审输入和独立证据基础上给出“可合入”“要求修改”或“证据不足”，并报告本次变更产生或暴露的可操作问题。

开放现实使用能够生成判断的原则表达；少量例子只用于校准，不构成分类、触发清单或适用范围。运行时工具语义、权限边界和其他封闭协议保持必要精度。

## 2026-08-29 分离研究搜索和上层判断

使用 `deep-research` 不把搜索工作自动留给 Root 或 `research-lead`。单项网络取证由 Root 直接交给 `web-researcher`；多路线研究由 `research-lead` 组织搜索执行者并综合。来源重要或结论需要由上层作出，不等于上层应亲自发现、收集或重复核验整条来源路线。

Root 或 `research-lead` 只有在取证报告已经定位到具体来源和片段，而一个明确矛盾或解释差异仍会改变自己负责的判断时，才读取解决问题所需的最小原文片段。这项定向核验不扩展成新的搜索路线。官方 Skill 使用章节中“亲自读取”的对象仍是已经选择的 `SKILL.md` 和它要求的指令或参考资料，不是网络研究材料。

## 2026-08-29 接入视觉黑盒验收

当代码阶段的完成声明包含可见界面、视觉反馈或完整用户操作路径时，`code-executor` 在候选能够运行后把首次用户视角的黑盒验证交给 `visual-usability-tester`，并根据报告安排修正和复测。没有取得这层证据时，不声明相应用户流程已经完成。

## 2026-08-29 明确代码评审结论和处理方式

`code-reviewer` 不再只提供问题清单。上级提交准确候选、期望结果、已接受约束、实际差异和验证证据后，它独立判断当前代码“可合入”“要求修改”或“证据不足”。这个判断只覆盖本次评审的代码，不替 Root 宣布整个用户任务完成。

“要求修改”的问题必须被修复、用技术证据反驳，或者在改变既定任务要求后重新判断；“证据不足”不能当作通过。`code-executor` 负责准备评审输入、安排返工和复审，并只把涉及其他模块、整体路线或上级任务要求的争议交回 Root。该结构参考 DeepSeek Harness 当前公开仓库的 [`dsh-code-review` Skill](https://github.com/deepseek-ai/deepseek-harness/blob/master/.agents/skills/dsh-code-review/SKILL.md)，但没有复制其中只适用于该仓库的检查项。2026-08-14 保存的本地旧 bundle 没有这份 Skill，不能用它代表当前上游仓库。

## 2026-08-28 取消共同阶段负责人 Base

阶段负责人只有 `code-executor` 和 `research-lead` 两个角色，而且代码阶段的最小成品、真实入口、大型修改和宿主验证门槛不适合直接约束开放研究。共同 Stage Base 被删除；两个角色分别以完整、自包含的专属提示词表达阶段所有权、下属组织、投入边界、停止条件和交回方式。少量相似文字允许分别存在，不再为了复用文字把不同领域压成同一种阶段方法。

Worker Base 继续保留，因为八个执行型角色共享相同的合同边界、越界上报、反无用功停止和直接上级交回机制。角色选择条件只留在 TOML `description` 和有调度权的上级提示词中；`worker`、`worker-luna` 和 `default` 不再在启动后重复判断自己是否应被选择。

FastCtx 的具体文件工具协议由运行时工具说明提供，不再复制进全局 `AGENTS.md`。共享中性 Base 只保留下位规则不得覆盖上位结果、权限和边界的层级原则。

## 2026-08-27 使用注册说明和共同执行层

角色的使用时机由各自 TOML 中的 `description` 提供。注册配置只引用角色文件，不再维护第二份容易漂移的描述。视觉测试的说明现在直接告诉上级何时使用该角色，Spark Worker 的说明直接提供独立额度和速度条件。

所有角色共同需要的 collaboration 工具选择、成品和验证规则由全局 `AGENTS.md` 承载。阶段负责人提示词只保留该阶段内部仍需判断的责任，不重复接口、CLI、等待和轮询过程。

## 2026-08-16 自包含重写

停止使用共享 XML 区块。原因不是避免文字重复本身，而是共享内容长期混入无关职责，并使权威源与实际角色文件发生漂移。七份生效提示词改为各自完整表达角色目的、行动、结果和边界；公共历史由本地 Git 保存，不再通过运行时共享段落维持一致。

## 2026-08-25 恢复全体角色的共同执行规则

执行型 subagent 不继承完整的主 agent Base。全局 `AGENTS.md` 因此补充所有责任人都会直接使用的规则：按合同结果完成责任，以当前事实工作，采用最低复杂度并在受阻时根据证据换方法，合并无依赖工具调用，制作可独立使用的成品，并按实际证据层验收。

整体路线、用户授权、Plan mode、模型成本和主 agent 的调度判断没有下放。`code-executor` 已经具备阶段内委派条件和共享状态边界，`research-lead` 也保留自己的研究分派规则，因此角色提示词没有复制共同段落。

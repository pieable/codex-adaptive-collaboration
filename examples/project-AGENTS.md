# 项目 AGENTS 示例

项目 `AGENTS.md` 保存进入这个仓库或目录后需要持续生效的指导。它可以包括项目约定、构建测试和评审要求、权限与兼容边界，也可以作为 agent 使用的稳定权威文件索引。更具体目录需要不同规则时，在相应目录放置更近的 `AGENTS.md` 或覆盖文件。

只列仍然有效并会改变执行的内容，不复制能够从源码或工具直接发现的一般事实。项目已有权威正文时，这里写入口、适用条件和必要优先级，不维护第二份容易漂移的内容。

## 项目专属规则

- 写入这个项目时必须遵守的兼容、权限和工作方式。
- 项目自己的构建、测试、发布和真实宿主验证要求。
- 只对特定目录、服务或代码评审生效的规则放在最接近其作用范围的位置。

## 权威文件索引

| 要了解什么 | 从哪里读取 | 何时需要 |
| --- | --- | --- |
| 用户需求和成品定义 | `docs/product.md` | 判断实现结果和取舍时 |
| 系统设计与稳定接口 | `docs/architecture.md` | 修改模块接口或集成路径时 |
| 当前实现入口 | `src/...` | 开始调查或实现时 |
| 验收方式 | `tests/...`、项目测试命令 | 准备声明完成时 |
| 当前阶段状态 | `docs/current-state.md` | 接续任务或组织多阶段工作时 |

不存在的来源不要为了填表创建。一个信息已经由更权威的文件承载时，这里只写索引和适用条件，不维护第二份正文。
